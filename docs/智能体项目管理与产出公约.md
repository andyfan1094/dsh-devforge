# 智能体项目管理与产出公约（0.18.0 / 0.19.0 / 0.61.0）

本文档说明天工造梦操作台「项目」页签的完整能力：项目登记、多端路径识别、扫描登记、智能体感知（模型工具与上下文注入）与产出公约（智能体文件秩序）。交付提交：一期 `1353ef7`（0.18.0）、二期 `1d97419` + 修正 `c1e83b9`（0.19.0）、三级 `outputs 项目优先两级布局`（0.61.0）。

## 一、能力总览

| 能力 | 入口 | 说明 |
|------|------|------|
| 项目登记 | 面板「新建项目」 | 名称/路径/描述/仓库/发布服务器/发布命令 |
| 扫描登记 | 面板「扫描登记」 | 浅扫常用代码根发现 Git 仓库，勾选批量登记 |

## 二、多端路径识别（换电脑也不怕）

### 2.1 数据语义

- `ProjectEntry.machinePaths`：`{ machineId → 本机绝对路径 }` 映射，随 store.db 备份同步到其他电脑。
- 本机 `machineId` 首次使用时生成 UUID，持久化在 store.db meta 表（键 `project.machine_id`）；各机互不相同。
- 读取清单时 `path` 恒等于「本机 machineId 的映射」（无映射时回退库里旧值），调用方无需关心映射细节。
- `pathExists` 为清单返回时的动态 stat 结果，不落库；失效条目显示红色「路径失效」徽标。

### 2.2 重定位（`POST /api/dsh-devforge/projects/relocate`）

- 载荷 `{id, path}`；校验新路径存在且为目录后，写入 `machinePaths[本机id]` 并同步 `path` 字段。
- **他机映射保留**：换回旧电脑时旧映射仍生效，各机各用各的路径。
- 新路径若能检出 origin 远端且与登记 `repoUrl` 归一化不一致，返回 `warn` 提示（不阻塞，交用户决断）。
- 归一化规则：小写、去协议前缀（https/git@/ssh）、`:` 转 `/`、去 `.git` 后缀与末尾斜杠。

### 2.3 自动匹配（`GET /api/dsh-devforge/projects/automatch`）

- 针对本机路径失效的登记项目，在扫描根里按「目录名 = 项目名或仓库地址末段」粗配，再以归一化远端**强校验**，只返回强匹配项（宁缺毋滥）。
- 面板在有失效条目时自动拉取建议，「重定位」弹窗预填候选路径。

## 三、扫描登记与数据保鲜

### 3.1 扫描登记（`GET /api/dsh-devforge/projects/scan?roots=`）

- roots 缺省用默认扫描根：`~/Documents`、`~/Documents/ds`、`~/Documents/projects`、`~/projects`、`~/code`、`~/dev`、`~/work` 中实际存在的目录。
- 下钻两层：根的一级子目录，以及名字以 project/projects/code/work/repos/workspace 结尾的二级目录。
- 只认 `.git`（目录或 worktree 指针）；排除隐藏目录、`node_modules`、`dist`、`build`、`target`、`.venv` 等。
- 已登记判定：候选路径与登记表本机路径完全一致 → 标记 `registeredId`，前端勾选禁用并显示「已登记」。
- 暂存隔离 HOME 下没有 Documents 等目录属预期现象，前端会提示「未找到可扫描的常用目录」。

### 3.2 保鲜与提取

- `POST /projects/refresh`：对存在的路径重跑检测，回填分支、origin 远端、托管类型与最近提交时间；检测不到远端时保留旧值不误清空。打开面板自动静默执行一次（挂载去重）。
- 最近提交时间：读 `.git/logs/HEAD` 末行，按「unix 秒 + 4 位时区 + 制表符」模式锚定（作者名含空格不影响）；面板显示为「今天/昨天/N 天前/日期」。
- `GET /projects/describe?path=`：`package.json.description` 优先，其次 README.md / README.zh.md / README.zh-CN.md / README.en.md 首个有意义段落（跳过标题、HTML、徽标行），200 字截断。

## 四、智能体感知

### 4.1 `devforge_project` 工具

- `action=list`：一行一项目的紧凑清单（名称 | 路径 | 仓库 | 分支 | 发布目标 | 失效警示）。
- `action=resolve&keyword=`：按名称精确 → 名称包含 → 路径包含 → 仓库地址包含的顺序模糊解析单个项目。
- `action=detail&id=`：完整详情。输出为纯文本，模型拿到即可直接使用。

### 4.2 项目卡注入

- 挂载点：约束注入的同一 system prompt 节（order 80，`composeAgentText` 动态求值）。
- 命中条件：会话 cwd 等于某项目的本机路径或位于其下（`machinePaths` 全部映射参与匹配——跨机后旧映射同样命中）。
- 注入内容：项目名、描述、仓库（类型+地址+分支）、线上地址、发布服务器、本机路径；路径失效时附「请向用户确认实际路径」警示。
- 项目清单与公约摘要各带 5 秒 TTL 缓存（index.ts 组装侧），避免系统提示每次装配都读库。

## 五、产出公约（智能体文件秩序）

### 5.1 默认分类学（面板可增删，projects 不可删）

| kind | 目录 | 用途 |
|------|------|------|
| projects | projects/ | 正经项目仓库，一项目一子目录（一等类别，贯穿项目管理） |
| tmp | tmp/ | 会话内临时文件，可随时清理 |
| scripts | scripts/ | 一次性脚本与批处理脚本 |
| downloads | downloads/ | 网络下载的文件 |
| backups | backups/ | 备份产物 |
| outputs | outputs/ | 交付物：按「项目/形态桶」两级归位（见 5.2） |
| notes | notes/ | 文档与笔记 |

### 5.2 outputs 两级布局（0.61.0 新增，项目优先）

0.60.0 及以前 outputs 的约束只有一句「交付物：图、文档、报告」，实测完全挡不住散落：该目录一度堆到 222 个顶层条目、191 个散落文件、1.33GB，交付包、验收截图、设计稿、报告、中间产物全平铺在一级。0.61.0 起 outputs 升级为**项目优先**两级布局：

```text
outputs/
├─ <项目名>/              一级＝项目（与 projects/ 同源，项目卡已每轮注入，判断成本最低）
│  ├─ 交付包/            安装包与构建产物（zip/exe/msi/tgz/tar/gz/7z/rar）
│  ├─ 截图/              验收、对比、现状截图（png/jpg/jpeg/webp/gif/bmp）
│  ├─ 设计稿/            设计稿与预览页（html/htm/css/svg）
│  ├─ 文档/              报告、说明、记录（md/txt/pdf/docx/doc/pptx/ppt）
│  └─ 数据/              结果数据（xlsx/xls/csv/json）
├─ _通用/                非项目产物（无法归属项目时的一级，禁止在 outputs 根下直接扔文件）
└─ _归档/                过期批次（体检时整体跳过，不要求两级结构）
```

- **命名硬约束**：`<YYYYMMDD>-<主题>-<状态>.<扩展名>`，状态 ∈ 草稿|验收|定稿|废弃，三要素缺一不可。
- **命名例外**：构建/发布包（zip/exe/安装包）保留工具生成的「名称_版本_日期」名，视为已满足（强改名会破坏可追溯性）。
- **中间产物**：`_diag-*`、`*.bak`、`*.tmp` 不得留在 outputs，放 `tmp/` 或删除。

### 5.3 注入与工具

- 公约摘要随约束注入每轮会话（enabled 开关控制），要求文件按类归位、禁止根目录散落；有二级结构的类别会额外渲染**形态桶清单、命名硬约束与归档规则**（0.61.0 前只有一行用途说明，是散落的根因），并指引模型使用 devforge_workspace。
- `devforge_workspace` 工具：
  - `locate(kind[, project][, sub][, workspace])`：返回类别目录绝对路径，缺失自动创建。带 `sub` 时按项目优先两级解析（`project` 省略则一级用 `_通用`）；`sub` 接受桶键（`packages`/`screenshots`/`mockups`/`docs`/`data`）或桶目录名（`交付包`/`截图`…）。workspace 缺省从执行上下文的 agent 会话 cwd 防御式解析。
  - `audit([workspace])`：**两段体检**——① 工作区根的散落**文件**按扩展名启发式给归类建议（脚本→scripts、媒体/图→outputs、文档→notes、压缩/备份→backups），目录/隐藏文件/未匹配扩展名不列；② **outputs 内部秩序体检**：识别堆在一级的散落文件、项目一级下未入桶的文件、被误当一级用的形态桶，给出「相对 outputs 的原路径 → 建议落位」并统计已就位数量。无登记项目名命中时一级建议用 `_通用`。
- **安全边界**：audit 只建议不动手（连目录都不创建，路径为纯计算），移动文件必须用户确认；locate 只创建公约目录，不移动任何文件。
- **路径安全**：项目名作为路径片段前必须过校验——拒绝目录穿越（`..`）、路径分隔符、隐藏前缀、控制字符、结尾点/空格与 Windows 设备名（CON/PRN/NUL/COM1…），非法即拒绝且不落盘。
- 配置 API：`GET/PUT /api/dsh-devforge/workspace/convention`；存储于 store.db settings 表（域 `workspace.convention`）。校验规则：kind 非空且不重复、dirname 禁路径分隔符与隐藏目录、projects 一等类别不可删除、形态桶 key 非空且不重复（dirname 同规则）。
- **配置迁移**：读取已保存公约时，仅对**缺字段**（`subdirs`/`naming`/`rules` 为 undefined）按 kind 回填默认值；显式传空数组（用户主动清空形态桶）必须被尊重，不得回填。


## 六、一键发布（0.19.1–0.19.3）

- 登记字段：`deployCommand`（发布命令）+ 每台发布目标各自的 `remotePath`（该台上的项目路径，缺省回退项目本机路径）。
- 执行：面板「发布」按钮 → confirm 明示命令与目标 → `POST /projects/deploy` → 复用远程运维激活后的同一 SSH/WinRM 引擎（同一连接池）逐台执行。
- 命令组装：`cd '<路径>' && <命令>`（ssh/POSIX）或 `Set-Location '<路径>'; <命令>`（winrm/PowerShell）；路径统一引号转义；输出 4000 字截断。
- 结果判定（0.19.3 修正）：对齐引擎 ExecResult（success / exitCode: number|null / timedOut / error）——超时→失败；exitCode 明确→0 为成功；exitCode 缺失（通道异常）→退回引擎 success 字段，仍不可知按失败处理；绝不把未知退出码静默当成功。多目标逐台收敛，单台失败不中断其余。
- 「在会话中打开」经调研不做：host 侧 `createAgent` 是子代理语义（origin='subagent'、委托深度、子代理生命周期），给面板强创用户会话属于滥用平台设计；正道是 GUI 前端「选择工作区→新建会话」。
- 校验语义：保存载荷「未传即保留旧值」；带 id 的部分更新允许省略 name/path（回退旧值），新增（无 id）必填。
