# 企业微信智能机器人桥（dsh-wecom）接入说明

> 能力定位：把企业微信的智能机器人接到天工造梦——在企微单聊或内部群里 @ 机器人，
> 消息进入一个独立的 DSH 会话（带工具、能改代码、能查资料），回复经长连接流式返回。
>
> 它解决的是「在聊天窗口里用上天工造梦」，**不是**接管个人微信号。
> 个人微信只有腾讯官方 ClawBot（iLink）这一条合法通道，与本文无关。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| 企业微信账号 | 企业或「个人组建团队」均可；**不要求企业认证** |
| 智能机器人 | 在**电脑客户端** → 工作台 → 智能机器人 → 创建 → 手动创建 → **API 模式** → **长连接** |
| 凭据 | 创建后拿到 **BotID** 与 **Secret**（长连接专用，不是回调模式的 Token/EncodingAESKey） |
| 网络 | 本机可出站访问 `wss://openws.work.weixin.qq.com`（无需公网 IP、无需域名备案） |

未认证企业的已知限制：通讯录约 200 人、内部群上限 500 人、不能直接加外部微信好友、
外部联系人上限 200。**内部小团队使用不受影响；要拉外部客户群必须先做企业认证。**

## 2. 配置

### 2.1 宿主配置（插件配置项）

```yaml
wecom:
  enabled: true
  botId: "<BotID>"
  secret: ""            # 建议留空，改用环境变量或配置文件
  cwd: "D:\\项目"        # 企微会话使用的工作目录
  agentPreset: cordis
  botName: "天工助手"     # 用于剥离群聊里的 @ 前缀
  welcomeText: "我是天工造梦，直接发消息即可。"   # 可空
```

### 2.2 凭据放文件（推荐）

写到 `~/.dsh/dsh-wecom.json`（跟随 HOME，暂存实例天然隔离）：

```json
{
  "enabled": true,
  "botId": "<BotID>",
  "secret": "<Secret>",
  "cwd": "D:\\项目",
  "agentPreset": "cordis",
  "botName": "天工助手"
}
```

### 2.3 凭据放环境变量（优先级最高）

```powershell
$env:DSH_WECOM_BOT_ID = "<BotID>"
$env:DSH_WECOM_SECRET = "<Secret>"
```

优先级：环境变量 > 宿主配置 > 配置文件 > 默认值。
Secret 永远不进日志、不进面板返回（面板只显示「是否已配置」）。

## 3. 使用

| 操作 | 行为 |
| --- | --- |
| 单聊发言 | 进入该成员的独立会话 |
| 群聊 @机器人 | 进入该群的独立会话（@ 前缀自动剥离） |
| `/help` | 返回使用说明（不建会话） |
| `/new` | 结束当前会话，下一条消息重建上下文 |
| `/stop` | 中止当前运行中的任务 |

会话号由「单聊:用户ID」或「群聊:群ID」哈希派生，**重启插件后上下文仍连续**；
`/new` 是唯一清空上下文的方式。

## 4. 能力边界与限制

- 同一机器人同一时间**只允许一条长连接**，新连接会踢掉旧连接。插件内部已做「新实例等旧实例关干净」的串行处理，不要在多台机器上同时跑同一个 BotID。
- 回复频率限制：单会话 30 条/分钟、1000 条/小时（官方）。
- 流式消息有 10 分钟硬上限；桥在 9 分钟时先收尾，任务完成后改用主动推送补发结果。
- 当前版本只处理**文本**（含图文混排里的文字、语音转写）；图片/文件/视频暂不解析，回复会说明。
- 主动推送前提：用户先给机器人发过消息；否则无法主动开新会话。

## 5. 本地联调（无需企微账号）

真实联调需要 BotID/Secret，且会把消息真的发到成员微信里。只想验证「桥是否能在真实
DSH 宿主里跑通订阅→收消息→投递→流式回复」时，用仓库自带的模拟服务端：

```powershell
# 1) 起模拟服务端（WebSocket 18888，控制接口 18889）
node scripts/wecom-mock-server.mjs --port 18888

# 2) 让桥指向它（仅该环境变量生效，不设即走官方地址）
$env:DSH_WECOM_WS_URL = 'ws://127.0.0.1:18888'
# 隔离 HOME 里写 enabled=true + 任意 botId/secret，然后启动宿主

# 3) 模拟用户发消息，再查服务端收到的帧
Invoke-WebRequest -Uri 'http://127.0.0.1:18889/send' -Method POST -ContentType 'application/json' `
  -Body '{"text":"你好","userid":"u1","chattype":"single"}'
(Invoke-WebRequest -Uri 'http://127.0.0.1:18889/frames' -UseBasicParsing).Content
```

期望看到：`aibot_subscribe` → `aibot_respond_msg(stream, finish=false, "正在处理…")` →
若干增量帧 → `aibot_respond_msg(stream, finish=true, "<最终答案>")`。
2026-10-20 已用该方式在隔离暂存实例（3081）完成单聊、`/help`、群聊 @ 三条链路验收。

## 6. 排障

| 现象 | 排查方向 |
| --- | --- |
| 日志无「企微长连接已就绪」 | 宿主配置 `wecom.enabled` 是否 true；BotID/Secret 是否为空 |
| 订阅失败 errcode 非 0 | Secret 是否用的是长连接 Secret；机器人是否被切成了「回调地址」模式 |
| 连接反复断开 | 是否有第二个实例在跑同一个 BotID（会互相踢） |
| 消息无回复 | 看日志是否出现「处理消息失败」；确认会话是否建成功（`session-wecom-*`） |
| 回复很慢 | DSH 一轮本身耗时；流式会先回「正在处理…」占位 |

## 7. 与个人微信 ClawBot 的取舍

| 维度 | 企微智能机器人 | 个人微信 ClawBot |
| --- | --- | --- |
| 合规 | 官方产品，无封号风险 | 官方产品，无封号风险 |
| 群聊 | 支持（内部群） | 不支持 |
| 主动推送 | 支持 | 不支持 |
| 账号门槛 | 需建企业/团队（个人团队免执照） | 个人微信即可 |
| 触达对象 | 企业成员/内部群 | 个人好友 |

结论：**内部协作、群聊、主动提醒 → 企微；自己随手用 → 个人微信 ClawBot。**
