# RAG 检索响应性修复验收（0.49.3）

## 问题与实证

用户报告执行 RAG 后整个会话及插件其它功能一起卡住。2026-10-14 使用生产 RAG 域的只读副本，在独立 Node 进程复现：10 个知识库、2803 篇文档、17748 个切块、15273 个被引用的缓存向量（2048 维）。副本不含账号、主机、API Key 或服务器密码。

旧版首次检索在 Host 同一线程中逐文档执行 `json_extract(data, '$.docId')` 切块查询；旧库只有 `(domain,id)` 主键索引，每次仍扫描整个切块域。2803 次查询共耗时 92316ms，冷检索总计 97396ms，事件循环最大观测间隔 97401ms。查询向量由本地假接口即时返回，排除了上游等待；旧版热检索仅 45ms。

## 修复内容

- 切块增加知识库、文档 JSON 字段的部分表达式索引；只覆盖 `rag.chunk`，原数据结构不变，旧库启动时幂等建立。
- 冷启动索引按知识库 `rowid` 游标分页，每页 64 块；每页批量读向量，不再逐文档扫描或一次展开全库高维数组。
- 页间通过 `setImmediate` 让出 Host 事件循环；Orama 插入每满 8ms 主动让出，HTTP、WebSocket、定时器可在重建过程中被调度。
- 同知识库并发检索共享一次在途重建；失败后允许重试，缓存失效按 Promise 身份保护，旧任务不能覆盖新版缓存。
- 入库、删除、保存设置、逐篇重嵌都使在途任务失效。分页期间若内容变化，请求明确提示重新检索，防止重复切块或新旧向量混用。

## 源码验证

- `tsc --noEmit` 通过。
- 最终全量回归 833 项通过，0 失败、0 跳过。
- 新增 7 项定向回归：分页无重漏及查询计划、并发共享与 I/O 调度、重建中删除、逐篇重嵌竞态、重建失败重试、就绪与缺向量过滤、长批插入调度。
- 独立审查对比旧算法与分页算法：518 个可检索切块的 id、正文、文件名、标题路径及分数一致；覆盖不同写入顺序、失败文档、缺失向量、孤儿块、其它知识库。

## 执行范围披露

只读审查子代理起步查记忆时误调用了一次生产 `rag_search`，与限定范围冲突，已即时披露并停止。该次调用已经返回；其后审查仅使用独立内存库与本地只读文件。上述性能基准及并发验收全部在独立进程/隔离暂存中执行，没有对生产进行循环压测。
