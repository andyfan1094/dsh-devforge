# CNB 代码托管对接说明

dsh-devforge 0.8.0 起内置 **CNB 代码托管能力**（cnb.cool，腾讯云原生构建），与既有 GitHub 能力并列，服务工厂的智能体可以直接操作国内仓库。

## 一、能力清单（10 个 cnb_* 工具）

| 工具 | 作用 |
|------|------|
| `cnb_auth_add` | 添加/更新 CNB 账号（保存访问令牌到本机 0600 文件） |
| `cnb_auth_list` | 列出已配置账号（不回显令牌） |
| `cnb_auth_test` | 验证令牌并返回认证用户名 |
| `cnb_auth_remove` | 删除本机账号记录 |
| `cnb_repo_list` | 列出我的仓库（支持名称/描述过滤） |
| `cnb_clone` | 克隆仓库（支持 `owner/repo` 简写） |
| `cnb_pull` | 快进拉取（--ff-only） |
| `cnb_push` | 推送（默认关闭） |
| `cnb_commit` | 本地提交（不推送） |
| `cnb_status` | 本地仓库状态 |

## 二、准备访问令牌（一次性）

1. 登录 [cnb.cool](https://cnb.cool)；
2. 进入 **个人设置 → 访问令牌 → 添加访问令牌**；
3. 按需配置到期时间、使用范围（公开/私有仓库）与授权范围（读写）；
4. 创建后复制令牌，然后任选一种方式保存：
   - 打开天工造梦面板 **代码仓库 → CNB → 账号**，粘贴令牌保存；
   - 或让智能体执行 `cnb_auth_add`（或直接告诉智能体令牌，由它保存）。

## 三、平台特性（与 GitHub 的差异）

- **仅支持 HTTPS + 访问令牌**：Git 认证用户名固定为 `cnb`、密码为令牌；**不支持 SSH**；
- **OpenAPI**：`https://api.cnb.cool`，认证头 `Authorization: Bearer <令牌>`；
- **仓库地址**：`https://cnb.cool/<组织路径>/<仓库路径>`，带不带 `.git` 后缀都可以；
- **公开仓库可匿名克隆**：未配置令牌时 `cnb_clone` 也能克隆公开仓库。

## 四、安全边界

- 令牌只存本机 DSH 凭据/插件统一 SQLite 存储（当前为 `devforge/store.db`，权限由本机 DSH 目录控制）；旧版 `dsh-cnb.json` 只在迁移时读取，成功后归档为 `.migrated.bak`，列表/摘要接口一律不回显；
- Git 操作时令牌经 **临时 HTTP 头** 注入，**绝不写入远端 URL 或仓库配置**；命令输出（stdout/stderr/命令串）自动脱敏为 `[redacted-token]`；
- `/api/dsh-cnb` 路由仅接受本机回环访问；
- **推送 / 强制推送默认关闭**：需在天工造梦面板 **代码仓库 → CNB → 安全设置** 里显式打开。

## 五、面板入口与配置开关

天工造梦面板 **代码仓库** 页签内分 **CNB / GitHub** 两个子页签（CNB 默认首位）。CNB 子页提供四个功能页：

| 子页 | 能力 |
|------|------|
| 账号 | 添加/更新/验证/删除访问令牌（令牌只写不读） |
| 仓库 | 按账号查询我的仓库，一键带入 Clone 参数 |
| 本地 Git | Status / Clone / Pull / Commit / Push（受安全开关约束） |
| 安全设置 | 默认账号、默认仓库目录、自动拉取、推送与强制推送开关 |

插件级 `enabled` 开关（dsh-devforge 设置里的 CNB 配置）控制是否注册 `cnb_*` 工具与路由（默认开启；未配置令牌时仅影响需要认证的操作）。

## 六、CNB 加密备份

代码仓库 → CNB → 加密备份页会把 `store.db` 与飞书配置打包加密后推送到 CNB 私密仓库：

- 配置 CNB 账号、私密仓库、6 位密码和 15 分钟/1 小时/6 小时/24 小时间隔；
- 立即备份会在内容无变化时跳过重复推送；
- 查看远端备份只读列出文件和大小；
- 恢复流程先输入密码预览来源机器与文件，再由用户确认覆盖；
- 跨机同步会跳过本机机器标识对应的 commit，只还原其他机器最新一次备份；
- 覆盖前自动保留 `.pre-restore.bak`，恢复/同步后必须重启 DSH 才完全生效。

备份仓库必须保持私密；不要把 6 位备份密码提交到 Git 或发送到聊天。
