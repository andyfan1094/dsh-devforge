# 沙箱提权参数清洗 · 排障手册

> 适用版本：dsh-devforge **0.33.2** 起（0.33.0 / 0.33.1 各有一次静默翻车，见 §4.1、§4.2）。
> 本文是**给未来的自己/任何人**看的：模型又报 `not strictly wider` 时，照 §3 三步走，不要重新猜。

## 一、症状（长这样就是它）

GPT / Codex 类模型在工具调用里惯性携带 `sandbox_permissions` / `justification`，触发宿主的硬失败：

```
Error: sandbox escalation to "danger-full-access" is not strictly wider than this call's current "danger-full-access" mode
Error: invalid justification: expected a non-empty sentence
Error: invalid escalation: sandbox_permissions requires a justification
```

表现：模型连续报错、反复重试直至会话作废。**提示词约束对这类模型无效**（已实测：教育式文本会被当成"有口子可用"）。

为什么 `danger-full-access` 会话必然失败：`@deepseek-ai/dsh-sandbox` 的 `WIDER_MODES` 里 `danger-full-access` 为空表 —— 已是最宽，任何提权请求都不可能是"严格更宽"。

## 二、修复原理（一句话）

在 `tools/pre-execute` 瀑布钩子里，把**可证必然失败**的提权字段从 `exec.arguments` 整体替换掉，工具体就再也看不到它们。

关键机制（别忘）：

- 该钩子拿到的是**活的 exec 对象**；`exec.arguments` **可以整体替换** —— `createExecution` 只对 JSON 快照做 `deepFreeze`，exec 自身要到 `notifyResult` 才冻结；工具体随后读的是 `exec.arguments`（`dsh-tools`: `dispatchToolBody` → `tool.execute(exec.arguments, exec)`）。
- **原地 mutate `exec.arguments` 会失败**（它被 deepFreeze 了），只能替换整个属性。
- 改参数靠 **mutate exec**，不靠钩子返回值（返回值只能 allow / deny / ask）。

代码位置：`src/sandbox-escalation-guard.ts`（纯函数 `judgeEscalationArgs` + `createEffectiveModeResolver` + `installSandboxEscalationGuard`），在 `src/index.ts` 的 `apply()` 里以 `prepend` 注册，与插件 `enabled` 开关无关、始终装载。

只剥三类**可证必然失败**的（其余一律原样放行，不改写合法提权与审批语义）：

| 类 | 情形 |
|---|---|
| A | 带了 `sandbox_permissions`，但 `justification` 缺失/空白/非字符串 |
| B | 只带 `justification`，没带 `sandbox_permissions` |
| C | 成对合法，但请求模式不是当前有效模式的严格更宽者（含 `danger-full-access` 会话的全部） |

## 三、三步定位（**先看反面证据，别只看"没报新错"**）

### 第 1 步：跑一键自检

```bash
cd /Users/andyfan/Documents/ds/dsh-devforge
node scripts/sandbox-guard-doctor.mjs
```

它会一次给出：运行中实例版本、已安装包版本与钩子标记、**两路证据**（独立留痕文件 + 宿主日志）的剥离/放行计数与最近记录，并直接给结论。

### 第 2 步：看两路证据（一票否决）

**第 1 路：独立留痕文件（0.33.2 起，推荐，独立于宿主日志路由）**

```bash
T=~/.dsh/storages/dsh-devforge/sandbox-guard-trace.jsonl
tail -5 "$T"          # strip = 剥掉了；keep = 放行了
```

- 有 `"action":"strip"` 记录 → 钩子在干活，问题不在清洗器（可带 `sessionId` 定位是哪个会话）。
- **一条都没有** → 钩子没生效，或还没有必然失败的提权调用发生。
- `"action":"keep"` 且**没有** `effectiveMode` 字段 → **危险信号**：模式没解析出来、走了保守放行。

**第 2 路：宿主日志**

```bash
grep -n "已剥离非法沙箱提权参数\|沙箱提权参数放行" /Users/andyfan/logs/dsh-web-restart.log | tail -20
```

- 两路一致 → 放心。
- 留痕有、日志无 → 功能正常，只是 `ctx.logger` 未注入走了 console 兜底（见 §4.2）。
- 两边都无 → 钩子没生效。

> 两次翻车都不报错：0.33.0 是"改了但没生效"，0.33.1 是"生效了但看不见"。**只看"没有新报错"必然得出错误结论。**

### 第 3 步：确认模型原样发了什么（会话日志取证）

会话日志是 **多帧 zstd**，`zstdDecompressSync` 只解第一帧会得到 1 条事件——必须用 CLI：

```bash
P=~/.dsh/sessions/--Users-andyfan-Documents-ds--/session-<会话id>/session.v3.jsonl.zstd
zstd -d -c "$P" > /tmp/sess.jsonl
grep -c "not strictly wider" /tmp/sess.jsonl      # 报错次数
node -e '
const fs=require("fs");
for (const l of fs.readFileSync("/tmp/sess.jsonl","utf8").split("\n").filter(Boolean)) {
  let ev; try { ev = JSON.parse(l) } catch { continue }
  if (ev.type==="tool/call" && String(ev.data.arguments).includes("sandbox_permissions")) {
    const a=JSON.parse(ev.data.arguments);
    console.log(new Date(ev.time).toISOString(), ev.data.name, JSON.stringify(a.sandbox_permissions), JSON.stringify(a.justification));
  }
}'
```

同时用**时间线对齐**判断结论：插件装载时刻 vs 报错时刻（`grep -n` 日志行号 + 时间戳锚点）。别靠推测作用域——0.33.0 排障时正是这里误判过一次。

## 四、已知根因清单（按出现概率）

### 4.1 `resolve` 解构调用丢 this（0.33.0 的真实翻车点：改了但没生效）

```ts
// ✗ 错：解构即丢 this，resolve 内部用 this.overrideOf/defaultMode/workspaceRoot → TypeError
const resolvePolicy = sandboxPolicyService?.resolve
resolvePolicy({ session })

// ✓ 对：保留接收者
sandboxPolicyService.resolve({ session })
```

异常被 try/catch 吞成 `undefined` → 钩子走"模式未知 → 保守放行" → `danger-full-access` 是合法升级目标 → 判定 keep → **一个参数都没剥，表面零异常零日志**。

对策：统一走 `createEffectiveModeResolver()`；回归测试 `tests/sandbox-escalation-guard.test.ts` 会断言"解构调用不得返回 undefined"。**任何吞异常的降级分支都必须留痕**（0.33.1 起的 `onKeep`）。

### 4.2 留痕写 `ctx.logger` 而插件未 inject logger（0.33.1 的翻车点）

```ts
// ✗ 错：inject 里没有 'logger'，cordis 访问未声明服务直接抛
//   "cannot get property ... without inject"，异常又被钩子的 try/catch 吞掉
ctx.logger.warn('...')

// ✓ 对：双通道 —— 官方 logger 优先，失败落 console，并且每次都写独立留痕文件
try { ctx.logger?.warn?.(line); logged = true } catch { logged = false }
if (!logged) console.warn(line)
trace({ time: new Date().toISOString(), action: 'strip', ... })
```

0.33.1 就是这样：剥离**完全生效**（真机 6 次带参数调用全部放行成功），但日志零记录，
排查时看上去和没修一样。教训升级版：**留痕不能依赖任何单一通道**。

### 4.3 钩子没被加载

- 运行实例版本旧：`curl -s --noproxy '*' http://127.0.0.1:3080/api/dsh-devforge/meta`
- 装错包/装错 profile：`node scripts/sandbox-guard-doctor.mjs` 会列出每个 profile 下的版本与钩子标记
- 改完源码忘了 `pnpm build` / 忘了重装 tarball（`lib/index.js` 才是运行时真正加载的）

### 4.4 宿主结构变更（升级后）

升级 DSH 后重点复核三处假设（都在官方包里，可能变）：

1. `tools/pre-execute` 仍是瀑布、仍能拿到活的 `exec`；
2. `exec.arguments` 仍可整体替换（官方若给它加 `writable:false` 就必须换方案）；
3. `ctx.get('sandboxPolicy').resolve({session})` 仍返回 `{ mode }`。

对应位置：`node_modules/@deepseek-ai/dsh-tools/lib/index.js`（`prepareExecution` / `dispatchToolBody`）、`@deepseek-ai/dsh-sandbox-policy/lib/index.js`。

### 4.5 宿主上游若改了校验语义

理想形态是**同级提权视为 no-op 而非报错**（已向上游建议）。若哪天官方这么改了，本清洗器仍无害：它只是提前把注定失败的字段拿掉。

## 五、免重启热修手法（生产不可随意重启时用）

已加载的插件代码改不了，但**它依赖的服务方法可以就地绑定**：

```js
const service = ctx.get('sandboxPolicy')
const original = service.resolve
const bound = (...args) => original.apply(service, args)   // 闭包绑回实例
bound.__devforgeBound = true
service.resolve = bound
```

于是已加载代码里那种"解构后调用"的写法也能正常工作。**关键是探测验证**：模拟解构调用

```js
const detached = service.resolve
detached({})     // 返回 { mode: ... } = 补丁生效；抛错 = 没生效
```

本次即以此法让运行中的 0.33.0 恢复正确行为。注意：动态插件/补丁不跨进程重启存活，重启后由已安装的新版本接管。

## 六、改动后的验收清单（缺一不可）

1. `pnpm test`（全量）+ `pnpm typecheck` 通过；
2. `pnpm build` 后**在 `lib/index.js` 里确认钩子标记**（别只改 src）；
3. 打包 → 装进 `~/.dsh/profiles/web` → 确认版本与钩子标记；
4. **真机反面证据**：让带参数的调用发生一次，确认**留痕文件**出现 `"action":"strip"`（并核对宿主日志）；
5. 模型侧确认：原会话重试同一操作不再报错。
