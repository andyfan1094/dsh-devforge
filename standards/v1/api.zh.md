# 后端 API 与分层规范（FhDoc v1）

tags: api, service, 后端, 分层, DAL, BLL, Utility

本规范用于后端服务。生成 .NET 服务时，必须按 `Api -> Bll/BAL -> Dal` 的方向组织代码；其他技术栈也必须映射为等价的表示层、业务层、数据访问层、模型层和通用层。

## 1. 项目与类的职责边界

- `Api` / 页面层：只处理 HTTP、页面交互、鉴权、请求绑定、输入格式校验、调用业务层和响应映射。Controller、Endpoint、Page 或 View 不得直接访问数据库、编写 SQL、承载领域规则、图像处理或 Excel/文件实现细节。
- `Bll`（也称 BAL，业务层）：承载用例编排、业务规则、业务校验、权限语义、事务边界和结果决策。业务层可以调用 Dal 和 Utility，但不依赖 HTTP 上下文、页面控件或前端实现。
- `Dal`（数据访问层）：只负责 DbContext、Repository、SQL/ORM 查询、持久化与数据库事务细节。Dal 不得包含页面逻辑或可变业务规则，不得替业务层决定流程。
- `Model`（实体/DTO/契约层）：只放领域实体、数据传输对象、枚举、请求/响应契约与明确的数据规则。实体不包含数据库访问、HTTP 调用或页面逻辑。
- `Utility/Utils`：只放跨模块可复用的通用能力，例如图像处理、Excel 读写、文件读写、编码/格式转换和通用校验。不得放领域业务、数据库访问或页面逻辑。
- 依赖方向必须单向清晰：页面/API 调用业务层，业务层调用数据层和通用层；禁止页面/API 直接调用 Dal，禁止 Dal 反向依赖 Bll 或页面层，禁止循环项目引用。

## 2. API 契约与数据访问

- 每个接口必须定义方法、路径、入参 schema/DTO、出参 schema/DTO、状态码和错误码；控制器仅负责协议适配，不得把数据库实体直接暴露为对外契约。
- 数据库访问必须在 Dal 内集中管理；SQL 一律参数化，禁止拼接外部输入。新增数据结构与迁移必须附带中文说明。
- 文件上传必须校验类型、大小、真实文件内容、存储路径与重命名规则；禁止用原始文件名直接拼接路径。
- 管理类接口必须做身份与权限校验，默认拒绝未授权的外网访问；内部调试接口不得意外暴露给普通用户。

## 3. 可观测与测试

- 使用项目既有或成熟开源日志框架记录结构化日志；启动/停止、接口请求摘要、关键业务开始与完成、数据写操作、外部调用、鉴权失败、重试与异常必须包含时间、动作、关联标识、耗时、结果和失败原因。
- 日志文件统一输出到项目根目录的 `logs/`，按日期或大小滚动；异常日志保留堆栈，但日志和对外响应都不得泄露密码、令牌、完整 API Key、Cookie、连接串或原始敏感文件内容。
- 提供健康检查端点 `/healthz` 或项目既定健康检查路径。
- 新增或改动 Bll 业务规则、Dal 查询、鉴权、金额、日期、文件或图像逻辑时，必须增加或更新针对性测试。无法自动化的外部集成测试必须标注依赖和可复现的人工验证步骤。
