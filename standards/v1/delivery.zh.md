# 交付与生产纪律规范（v1）

tags: delivery, 交付, 生产, 红线, 暂存, 发布

本规范适用于一切涉及发布、部署、升级的交付任务，以及任何会触碰生产环境的操作。规则之间冲突时，红线优先于流程，流程优先于惯例。

## 1. 生产红线（最高优先级，不可绕过）

1. **生产不是试验田**：生产实例承载真实凭据、长连接、会话库与任务账本，任何改动都不允许先在它上面试。
2. **生产重启必须用户明确确认**：无论改动多小，只有用户明确说「重启」后才允许执行生产重启命令；自动重启、顺手重启一律禁止。
3. **禁止改生产凑效果**：不得直接修改生产安装目录、生产数据库（如 store.db）或线上文件来“看起来生效”；一切改动必须落在正式项目源代码，走完整交付链路。
4. **凭据与敏感信息零泄露**：令牌、密码、密钥绝不进入代码、提交历史、聊天输出、文档或 URL；Git 用户名固定、令牌走临时注入。

## 2. 标准交付链路

按顺序完整执行，禁止跳步：

```text
① 源仓库验证：typecheck + build + 测试（针对性 + 全量回归）全绿
② 中文提交并推送远端（按项目约定，默认 CNB origin）
③ 发布产物：打包、生成校验值、更新清单（latest 与版本化包必须是同一字节副本，SHA-256 一致）
④ 上传发布源并线上核验（清单、下载、SHA-256 三方一致才算发布成功）
⑤ 安装到目标 profile（安装不等于重启，生产进程保持不动）
⑥ 隔离暂存实例真实运行，人工过目验收
⑦ 用户明确确认后重启生产
⑧ 确认生产版本与功能，关停暂存实例
```

## 3. 暂存验收硬性要求

- 暂存实例必须使用**独立 HOME**（隔离凭据与会话库），禁止与生产共用 HOME 打补丁起实例。
- 暂存 overlay 必须显式禁用：飞书桥（同 appId 双长连接会分流事件）、桌面宠物（双实例重复弹窗）；暂存实例的自动备份同步必须停用（防跨实例备份污染）。
- 暂存固定使用与生产不同的端口（如 3081），启动前确认端口空闲，启动前先离线核对补丁命中。
- 暂存只做真实集成验收，不在暂存内执行插件安装/升级。
- 验收确认生产侧无影响后，关停暂存实例。

## 4. 证据与核验纪律

- 工具返回的文件路径不代表文件真正落盘可用；声称「已生成/已发布/已生效」前必须实际核实文件存在、接口返回、版本号与校验值。
- 版本号、发布状态等可变事实以实时核验为准（查询远端清单/接口），不得仅凭记忆断言。
- 发布包的 SHA-256 必须在本地、清单、线上下载三方核对一致；清单 latest 与版本化包指向同一字节副本。
- 验收结论要有证据：测试通过数、构建产物、接口返回、校验值、人工确认记录。

## 5. 失败与回退

- 任何一步验证失败立即停止，修复后从该步重跑，禁止带病交付。
- 升级前保留可回退版本（旧包、旧提交、备份）；回退同样需要验证。
- 生产重启后必须确认版本与关键功能正常，异常时立即说明并准备回退方案。

## 6. 提交纪律

- 提交信息用中文，格式如 `feat(模块): 变更说明`、`fix(模块): 修复说明`。
- 只提交本次任务的文件，不把无关改动、日志、私有配置、数据库、密钥或测试产物带入提交。
- 版本号变更、发布元数据（清单/校验值）随功能变更一同提交。
