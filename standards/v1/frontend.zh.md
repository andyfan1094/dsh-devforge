# 前端页面层规范（v1）

tags: frontend, 前端, 页面层, 分层, UI美观

## 1. 页面与组件职责

- 页面、组件和 ViewModel 只负责展示、交互状态、输入校验提示和调用 API，不得直接访问数据库、复制后端业务规则或实现文件、图像、Excel 等通用处理细节。
- 组件单一职责；展示、逻辑和样式分离。跨组件通信优先 props、事件或明确的状态容器，避免全局单例泛滥。
- 所有后端调用集中在 API 客户端层；组件不直接 `fetch`，错误必须以 toast 或内联状态反馈给用户，禁止静默吞错。

## 2. 可读与复用

- 每个新增或修改的页面、组件、公开方法和复杂交互流程必须有中文注释，说明业务目的、状态变化和异常边界。
- 先复用已有通用组件、API 客户端和 Utility；仅在多个页面都需要且没有领域业务语义时创建通用组件或工具。
- 优先使用最简单、可读的状态与渲染逻辑。复杂状态机、缓存或抽象只在简单方案无法满足明确用户需求时引入，并说明原因。

## 3. UI 美观规范（硬性要求）

生成页面默认就要达到"可直接交付用户使用"的视觉完成度，禁止以浏览器裸默认样式交付。核心方法：先定设计 token 再写页面；建立层级靠克制的变化；留白宁多勿少。

### 3.1 设计 token 先行
- 动工前先确定设计基调，并落成 CSS 变量或 Tailwind theme：主色 1 个 + 中性灰阶 9~10 档（如 50~950）+ 成功/警告/危险语义色；圆角统一 2 档（卡片 8~12px、控件 6~8px）；阴影至少 2 档（悬浮、弹层）。
- 推荐默认栈：Vite + Tailwind CSS，token 命名沿用 shadcn/ui 风格（--background/--foreground/--primary/--muted/--border 等），便于暗色模式整体切换；需求指定其他技术栈时可替换，但 token 原则不变。
- 所有颜色、间距、圆角、字号必须引用 token，禁止在组件内散写魔法值。

### 3.2 色彩与文字灰阶
- 页面色彩比例约 6:3:1：中性背景与文字为主体，品牌主色用于关键动作与强调，点缀色只给状态提示。
- 文字用灰阶分层建立层级：主文字约 90% 灰、次要文字约 60%、占位与禁用约 40%；避免大面积纯黑 #000 与纯白 #fff 直接对撞。

### 3.3 排版与层级
- 字体用系统字体栈；同一页面字重不超过 2 种（常规 + 半粗），字号层级 4~5 档。
- 建立层级一次只动 1~2 个维度（字号、字重、颜色），禁止同时放大、加粗又变色。
- 行高随字号走：正文 1.6~1.7，标题 1.2~1.3；正文每行约 65~75 个字符。

### 3.4 间距与布局
- 8pt 网格：间距只取 4/8/12/16/24/32/48；同组元素靠近、不同分组拉开。浏览型页面留白宁多勿少；看板/管理页按 3.8 的紧凑密度执行。
- 内容区设最大宽度并水平居中（看板类约 1200px，文档类约 720px）；页面必须响应式，覆盖桌面与手机宽度。

### 3.5 状态完整性
- 列表与详情页必须实现：加载态（骨架屏优先）、空态（一句说明 + 行动按钮）、错误态（说明 + 重试）、成功反馈（toast 或内联提示）。
- 所有可交互元素必须有 hover、active、focus-visible 三态；过渡时长 150~200ms，只过渡颜色、阴影与变换。

### 3.6 暗色模式
- 默认支持暗色模式：token 双主题 + 根元素类名切换。暗色不是反色：背景分层抬升（越浮层越亮）、主色降饱和、阴影弱化改用边框分层。

### 3.7 图标与细节
- 图标单一来源（如 lucide），同页尺寸与线宽统一；图片与图表占位用固定宽高比，防止布局跳动。
- 同层控件高度一致；主按钮每屏唯一；数字列用等宽数字（font-variant-numeric: tabular-nums）对齐。

### 3.8 信息密度与排版（核心诉求：一屏多呈现、不拥挤）
- 密度分两档：浏览型页面（介绍/文档/落地页）用舒适密度，分组间距 24~32px；看板/管理页（表格、列表、监控、后台）默认紧凑密度——分组间距 12~16px、表格行高 36~44px、卡片内边距 12~16px。
- 宽屏利用：内容区用 12 列栅格；≥1280px 时统计卡片 3~4 列、列表与详情双栏（主区约 2/3 + 侧栏约 1/3）；禁止把宽屏内容挤成一条窄柱，也禁止无栅格的自由堆叠。
- 表格规范：数字列右对齐并用等宽数字；表头吸顶；行 hover 高亮；行操作固定右侧且只放高频 1~2 个，其余收进“更多”；≥5 列提供列显隐；每页 20~50 行。
- 渐进披露：一屏放不下的信息用标签页、折叠面板或抽屉收纳；默认只展开最重要的 1~2 组；禁止把全部信息平铺成长页。
- 工具栏合并：搜索、筛选、批量操作合并为一行工具栏；标题行右侧放主操作，不单独占一行。
- 防拥挤底线：紧凑≠塞满——相邻两块内容间距≥12px，文字距边界≥8px，每屏主操作≤1 个，图标必须带文字标签或 tooltip。

## 4. 交付

- 完成后本地构建通过（例如 `npm run build` 或 `tsc --noEmit`）再交付。
- 关键流程验证正常、空数据、错误响应和权限不足等状态，并在交付摘要中说明页面职责与 API 边界。
- 交付前按第 3 节做视觉自查：token 是否全覆盖、加载/空/错误/成功四态是否齐、响应式与暗色是否可用、信息密度是否符合页面类型（浏览=舒适/看板=紧凑），并在交付摘要中说明设计基调（主色、灰阶、圆角、字体层级、密度档位）。
