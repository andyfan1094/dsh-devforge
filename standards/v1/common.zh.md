# 通用开发规范（v1）

tags: common, 基础

本规范适用于所有服务生成任务；子代理必须在动工前通读并逐条落实。

## 1. 注释铁律

- 新增业务代码必须直接写清晰的中文注释，重点说明：入口、关键流程、去重/安全边界、异常处理。
- 数据库新增表和字段必须写清晰的中文 COMMENT（Navicat 可直接查看）。
- 不允许"只靠外部文档说明、代码里零注释"。

## 2. 目录与工程

- 服务必须独立目录，入口文件清晰（如 src/index.ts 或 main.py）；禁止把入口埋在深层嵌套里。
- 依赖最小化：能用标准库/已有依赖解决的不新增包。
- 配置与代码分离：密钥一律走环境变量或本地私有配置文件（0600 权限），严禁硬编码、严禁写入任何文档或提交历史。

## 3. 异常与边界

- 所有外部调用（HTTP/DB/文件系统）必须有 try/catch 与超时；失败要打日志并给出可读错误信息。
- 输入校验前置：路径必须校验绝对/相对与白名单；外部输入不信任。
- 幂等与去重：重复触发同一动作不能产生重复副作用。

## 4. 交付自检

完成后必须输出交付摘要：文件清单、启动方式、验证命令（或自测步骤）、已知限制。
