# Data visualization craft rules

单张图表与数据呈现本身的跨品牌工艺规则。`DESIGN.md` 决定图表用什么颜色、字体与圆角，本文决定**它必须先满足哪些编码、刻度、色序、数值与无障碍条件才算合格**。

> **范围边界**：本文只管一张图内部与一组图的呈现工艺，不管页面。控制台骨架、导航壳层、卡片编排、筛选栏位置、刷新频率与时间戳归属一律见 `dashboard-console.md`；需要精确到逐行逐列的数值时见 `data-tables.md`；配色令牌本身见 `color.md`；对比度与焦点环的全部基线见 `accessibility-baseline.md`。

> 依据一手来源整理：IBM Carbon Design System（Chart anatomy / Axes and labels / Color palettes / Legends / Simple charts）、Financial Times Visual Vocabulary、Nielsen Norman Group（Dashboards: preattentive、Choosing Chart Types、Clutter-Free、Contrast）、W3C WCAG 2.1 理解文档（1.1.1、1.4.1、1.4.11）、MDN（`font-variant-numeric`）、Data Viz Project 的按功能分类。逐条对应见文末「来源」。

## 一、图表选型决策表

先定**意图**，再定图形。意图写不出来，说明还没想清楚这张图要回答什么问题。六类意图的判据如下（数据量档位为经验区间，其余判据出自来源）。

| 意图 | 优先图形 | 适用数据量 | 不该用 | 陷阱 |
|---|---|---|---|---|
| **比较**（谁更大） | 类别名长用横向条形图，类别名短用柱状图 | 类别 5–10 个；超过 20 个改「前 10 + 其他」 | 饼图、雷达图、面积图、气泡图 | 用面积或角度代替长度；类别不按值排序，读者要自己做排序 |
| **构成**（占多少） | 单行 100% 堆叠条（首选）；类别 ≤5 且只有一层时可用饼图或环图；层级构成用树图 | 饼图 ≤5 片；堆叠条 ≤6 段 | 3D 饼图、双环饼图、超过两层的多级饼图 | 用饼图比较相邻扇区；用堆叠面积读单条精确值 |
| **分布**（值怎么散开） | 连续量用直方图；多组对比用箱线图；样本少用点条图；看集中度用累积曲线 | 直方图分箱 5–20 个；点条图 ≤200 点 | 折线连无序分类；饼图 | 分箱数随手取；隐藏离群点；只给平均值不给离散度 |
| **相关性**（两个量一起变吗） | 散点图；第三变量用气泡直径；时间序列之间的相关用连线散点 | 散点 ≤1,000 点，超出改用抽样、分箱或密度图 | 折线连两个不同变量 | 暗示因果；强加趋势线却不标拟合优度与样本量 |
| **随时间变化** | 连续量用折线；离散周期且只有一条系列时用柱/列；状态型用阶梯图；带不确定性的预测用扇图 | 折线 ≤5 条，超出拆子图；列 ≤12 个周期 | 饼图、雷达图 | 时间轴间隔不等却不标注；把「周期合计」与「时点值」画进同一轴 |
| **排名**（名次本身是重点） | 排序后的横向条形图；跨两期名次变化用斜率图；强调单值用棒棒糖图；多类别名次用点条图 | 排名条目 5–15 个 | 用颜色深浅表达名次；用面积表达名次 | 名次变化用面积或角度；跨期排名画成两张互不相干的图，读者接不上 |

选型的底层依据是**编码强度有次序**，不是风格偏好（NN/g）：人对长度与二维位置的比较既快又准，适合承载定量信息；面积与角度只能粗看，无法判断「大了多少」；颜色能立刻看出差别，但人对颜色没有顺序感，**不能用来表达数量大小或量级**。把最重要的比较放进弱编码通道，是图表最容易犯的结构性错误。

三条判定细则：**① 一图一意图**——同一张图不要同时回答「谁更大」和「占比多少」，需要两个答案就出两张图，或改用 §2 的量 + 率窄组合。**② 单点数据不出图表**——只有一根柱或一条线时它是指标卡，只是被画成了图（与 `dashboard-console.md` 同一约束）。**③ 先把类别排序再画**——比较与排名类意图下按值排序是默认动作；保持数据源顺序只在顺序本身有含义（时间、流程、等级）时才成立。

## 二、被禁的图表做法

每条前半是判定，命中即失败。

| 被禁做法 | 判定 | 可接受替代 |
|---|---|---|
| 3D 图形（3D 饼图、3D 柱、带透视的环图） | 出现任何第三维透视即失败 | 平面图形；需要强调用颜色或直接标注 |
| 柱状图 / 面积图 Y 轴不从 0 起 | 基线不在 0 即失败，无例外 | 轴从 0 起；差异太小就把差值单独画成一张图 |
| 折线图 / 散点图截断 Y 轴但无标记 | 有截断而无可见轴断裂标记即失败 | 补显式轴断裂（见下）；或把整条轴保留 |
| 双 Y 轴 | 把两个不同量纲的**同类量**（两条都是金额、两条都是人数）各配一轴塞进一张图即失败 | 拆成两张图；或指数化到同一基准（=100）后单轴叠放 |
| 面积误导 | 用面积、角度、体积表达需要精确比较的量即失败 | 换以长度为编码的图形；面积只用于「量级差异极大、只需看出粗细」的场合 |
| 彩虹色序 | 用 HSL 色相环均分生成分类色，或让颜色沿色相环循环取用即失败 | 用经设计并固定顺序的离散分类色序（见 §4），严格按序取用 |
| 无基线的柱状图 | 柱体一端悬空、或柱高不代表从 0 起的量即失败 | 柱体必须从共享基线生长 |
| 用颜色表达数量大小 | 无图例说明的连续色块，或用分类色表达大小即失败 | 数量用位置或长度；颜色只做分类或（在连续色序下）做强度的第二编码 |
| 指针仪表 / 半环仪表做精确比较 | 用它读出具体值或比较两组即失败 | 指标卡 + 基准对比；仪表只允许做「处于哪个区间」的粗判断 |

**Y 轴截断的唯一可接受例外**：折线图与散点图（趋势型、连续量的方向变化，而非尺寸比较）允许裁掉空白区间，但三条必须**同时**满足——**①** 该图表达的是趋势方向或离群点，不是柱与柱、扇区与扇区的相对大小；**②** 断点处有显式轴断裂标记（Carbon：用正弦线替掉直线段，Y 轴断裂固定 16px，X 轴断裂随图宽浮动且最小 16px）；**③** 断点区间内若有数据，该段线宽降为 0.5px 并隐藏数据点圆点，若无数据则区域留空不画线。柱状图、面积图、饼图、任何 part-to-whole 与比较类图表**没有这个例外**：Carbon 明确要求这几类的数值轴一律从 0 起，因为截断会把小差异放大成看起来显著的差异。

**双 Y 轴的唯一可接受例外**：量（柱或面积）与率（线）的组合，即 FT《Visual Vocabulary》列为合法用法的 line + column。落地时必须同时满足：两条轴各自标注单位；轴的排布与对应系列在视觉上绑定（谁用左轴、谁用右轴不能靠猜）；不引入第三个量纲。其余场合一律拆图。

## 三、坐标轴与刻度

- **零基线**：柱、面积、饼、堆叠条一律 0 起。折线与散点可截断，但按 §2 的三条约束执行。轴断裂不是「藏起来」的手段，刻度标签必须仍然连续可读。
- **刻度数量**：主刻度（含 0）取 **4–6 条**（经验区间）；网格线条数 ≤ 主刻度条数。觉得网格太密时，先**整档抬高轴单位**（把单位从 10,000 提到 20,000）来减少网格线与标签，而不是靠加粗或淡化掩盖（NN/g）。
- **刻度步长必须固定**：时间轴不得为迁就数据可用性而改变刻度增量；确需压缩间隔，用轴断裂显式标注，不许静默改步长（Carbon）。
- **步长取可心算的数**：1 / 2 / 2.5 / 5 / 10 乘以 10 的幂，禁止 37、74、111 这类需要计算器才能比较的刻度（工程判据）。
- **网格线强弱**：轴线与网格线必须差一档。轴线、刻度线属于「理解内容所必需的图形」，与相邻色对比 ≥ **3:1**（WCAG 1.4.11）；网格线不承担这一阈值，但必须「可见且不抢」——虚线或低一档透明度，且不得比数据线更显眼（工程判据）。X 向竖直网格默认删掉，只在需要按列对位（如分组柱）时保留。
- **有数据标签就删冗余轴**：给每个柱加上数值标签后，Y 轴与网格线不再承担取值功能，此时它们从工具变成 chartjunk，应当删除（NN/g）。反过来，如果目标是「感受量级差异」而不需要精确值，保留网格线、不加数据标签才是正确取舍（NN/g）。
- **标签角度**：横向条形图用于长标签（任务名、功能名、地区名），让标签水平可读，不旋转、不缩写（NN/g）。竖柱图标签一旦需要旋转超过 45° 才能放下，判失败，改用横向条形图或把类别数减少到可水平排布的规模。
- **标签不得省略成不可解缩写**：空间不足时用「完整但更短的词」，不要用代号。「查找 5 月 12 日的账单」优于「任务 2」（NN/g 的原始示例即此类）。
- **轴标签默认给**，且要能脱离图表标题独立理解；只有内容自明（如纯日期轴）才允许省略（页面级的轴标签决策见 `dashboard-console.md` §8，此处不重复）。
- **时间轴的界标标签**：数据跨入新的日、月、年时，把该刻度标签半粗体标为界标，为后续标签提供上下文（Carbon）；日期时间格式用本地化格式或用户偏好，同一图内不混用相对与绝对时间。
- **单位与数量级写法**：单位进**轴标题**，不进刻度标签——写「营收（百万元）」而不是在每个刻度后写「百万」。用 1.2k / 3.4M 这类缩写时，必须在轴标题或图注里定义 k 与 M 的含义，同一页内不得 k 与「千」混用，同一页所有图表不得切换计量单位（页面级一致性见 `dashboard-console.md` §5）。
- **轴范围不要贴着数据走**：最大值贴到绘图区顶边会让读数困难；给顶部留出容纳数据标签的空间（工程判据）。

## 四、颜色

三种色序，用途不可互换。

| 用途 | 色序 | 取值纪律 | 禁忌 |
|---|---|---|---|
| 离散、彼此无内在顺序的类别 | 分类（categorical / 定性） | 严格按设计好的固定顺序取用（Carbon 的用途色序为 01→14，序列经设计以最大化**相邻色**的对比）；类别数控制在 8 个以内（经验区间，超过后相邻色区分度下降） | 循环取色、跳过顺序取色、按数据源顺序随机分配 |
| 连续量（密度、强度、比率、热力） | 连续（sequential / 单色阶） | 单一色相的单调明度阶；**浅色主题最深的色表示最大值，深色主题最浅的色表示最大值**（Carbon） | 用渐变代替连续色序；一图叠多个渐变（Carbon：多重渐变通常不可访问） |
| 存在自然中点（0、目标、均值、冷热） | 发散（diverging） | 两臂两种色相、明度对称，中点必须是中性浅色；红-青用于冷热类数据，紫-青用于无温度关联的数据（业绩、销售、变化率）（Carbon）；发散色序不区分明暗主题（Carbon） | 中点用饱和色；两臂明度不对称，导致一侧看起来更重 |

**相邻类别的区分底线**：相邻系列（含堆叠段、相邻扇区）的**相对亮度差达到 3:1** 才算「颜色之外的额外视觉差别」（WCAG 1.4.1 的判定说明）。因此选分类色序时不能只看色相是否不同，必须检查灰度下的明度差。

**色盲友好底线**（不可再降的要求）：

- 禁止红-绿配对作为唯一区分手段。约 **8% 男性、0.5% 女性**存在某种色觉缺陷（NN/g 给出该量级，并说明随族群变化）。
- 明度与色相**双通道**同时区分：既换色相也换明暗（NN/g：亮度相近的纯色最难区分，深浅加色相更有效）。
- 通过判定：图表转灰度后仍能区分所有系列；做不到就必须叠加第二编码（线型、点形状、纹理、直接标注）。
- **纹理是合法手段**：Carbon 允许用纹理替代或叠加在颜色之上，以服务视觉障碍用户。

**深浅背景对比**：

- 图形对象（数据线、柱、点、扇区边界）与相邻色 ≥ **3:1**（WCAG 1.4.11），且计算值**不四舍五入**——2.999:1 不合格。
- 抗锯齿会让细线与小图形在屏幕上比标称颜色更淡，实际对比低于计算值；因此避免 1px 以下的细线，或选一对明显高于 3:1 的颜色（WCAG 1.4.11 的说明段落即为此）。
- 深色主题不是「把浅色主题的色值搬过来」，连续色序的明度方向必须翻转（Carbon）。
- 文字（轴标签、图例、数据标签）与背景 ≥ 4.5:1；这是文字阈值，与图形对象的 3:1 分开判。

**强调色预算**：先全部用灰阶画完，再给「这张图要说的那一条」上色（NN/g 转述 Schwabish 的 "Start with gray"）。一张图最多一个强调色；标题中复述该结论的短语可以与强调色同色以建立关联（NN/g）。全图所有系列都鲜艳，等于没有强调。

## 五、图例与标注

- **直接标注优先于图例**。Carbon 的措辞很直接：能避免图例就避免，直接在图上标注数据表示。原因是图例依赖视觉关联，读者必须在图与图例之间来回看（NN/g 同样指出这是图例的主要负担）。
- **单系列不要图例**。只有一类数据或只用了一种颜色时，图例是冗余元素（Carbon），此时用标题说明这一系列是什么。
- **图例位置**：默认底部，顶部次之（Carbon——空间紧张时优先这两处）；左侧利于排版对齐（前提是图表周边元素不过于拥挤）；右侧用于空间充裕、需要最大化上下文的场合，移动端可回退为堆叠。**overlay 仅限地理图**，且图例背景不透明度必须为图表底色的 80%（Carbon）。
- **图例顺序 = 数据顺序**：与堆叠顺序、分类色序取用顺序一致。按字母序或按后端返回顺序排图例，会让读者无法在图与图例之间建立稳定映射（工程判据，源自 Carbon 的色序纪律）。
- **图例溢出**：默认最多两行，超出用「查看更多」展开；图例区高度**不得超过图表高度的 30%**，超过后改为纵向滚动（两者均出自 Carbon）。
- **图例禁用缩写**，标题与轴标签同理（Carbon）。
- **图例交互**：悬停某一类别时其余类别不透明度降到 **30%**；点击隔离该类别并进入选中态，全部选中时回到默认态（Carbon）。
- **隐藏图例是被劝阻的**：Carbon 明确指出隐藏图例会降低清晰度且不可访问，只在移动端单类别场景容忍，且必须提供「查看图例」入口，点开后以模态列出可逐项开关（Carbon）。
- **标题写结论，不写数据名**（NN/g 的 active title）：差的是「设计改版前后的登录率」，好的是「改版后登录率提升 29%」。标题不承担结论时，读者要在图里自己找重点；把单位从标题挪走后必须补回轴标签（NN/g）。
- **参考线**：目标值、均值、基线用参考线，且**必须带名称标签**（「目标 80%」）。只画一条线不给名字，读者会以为那是数据。
- **注释预算**：每图注释 ≤2 条（与 `dashboard-console.md` §8 同一约束）；此处补充判定——注释不得遮挡数据点，不得与参考线混用成第三种标记语言。
- **时间序列的注释挂事件**：改版、大促、事故这类上下文要作为 callout 画在图上，不要只在讲述时口头说明，否则图表被转发后上下文全部丢失；需要读者记住「哪条是哪条」的图表，等于把工作交给了读者的短时记忆（两者均出自 NN/g）。

## 六、数值呈现

- **有效位数**：刻度按可心算取整；图上直接标注的数值给 3 位有效数字（经验区间），完整精度放 tooltip 或数据表。同一图内同一指标的小数位必须一致，百分比的小数位也必须一致。
- **每个数字都要有对比对象**：NN/g 的判据是「人必须拿一个数去比另一个数才能解释它」。同比（较去年同期）与环比（较上一周期）必须写清基准是谁；至少给出绝对变化量与相对变化量中的一个，且能追溯到两个原始值。
- **缺失数据：默认断线，禁止插值，禁止静默补零。**
  - Carbon 的硬要求：数据不可用的区间**绝不插值**，并且必须**标注缺口的起点与终点**（不画线、区域留空或用纹理表示）。
  - 连成平滑曲线跨越缺口，等于声称你测过那段；补零则等于声称那段时间的值为 0，两者都是编造。
  - **补零唯一允许的条件**：该时间点的「量」确实是 0 且有数据源可证（例：当日订单数确为 0）。此时仍须在图注写明「0 为实测值」，并与缺口区分显示。
  - 分类轴上缺失类别不画空柱；改为在数据表里列出并标注「无数据」。
- **负数与零**：零线必须比网格线重一档并贯穿全图；发散柱从零线向两侧生长；正负两段用发散色序的两臂取色，不要用同一条连续色阶跨零（否则零附近两端颜色近似，正负难辨）。
- **不混量纲**：累计量与增量、绝对量与比率不得同轴（属 §2 的双 Y 轴滥用）。
- **单位与量词**：单位统一写在轴标题、卡片标签或列头，不进每个数值内部；量词（单、次、人）与单位分开——「12.4 万」可以，「12.4 万单」不进入大数字本体。

## 七、指标卡里的数字

- **一张卡 = 一个数 + 一个词**。Carbon 对 KPI 的定义即「一个数字加一个单词描述」（例：「15,250 浏览器」「总 450」）。
- **大数字排版**：字号 ≥32px（经验区间），并强制开等宽数字，避免数值刷新时卡片宽度抖动（OpenType `tnum`，MDN）：

  ```css
  .kpi-value {
    font-size: 32px;
    font-variant-numeric: tabular-nums;
  }
  ```

- **大数字不加负字距**。display 档字号常被加负字距，但多张卡并排时数字必须等宽对齐，`letter-spacing` 取 0 或正值；`-0.02em` 这类值是排版事故（工程判据）。
- **单位用前后缀**：小后缀（万、M、%）紧跟数字，量词放标签。同一卡片上不同指标的后缀规则必须一致。
- **每张卡必须有基准**：上一周期、目标值、同组中位数，三者至少有一个；没有基准的孤立数字不得单独出现在监控视图（与 NN/g「数字必须有对比对象」同一判据）。
- **趋势必须三件套齐全**：方向符号 + 绝对差 + 基准名。写「↑ 1,240（较上月）」合格；只写一个红色向上的箭头不合格，因为读者无法判断幅度与基准。
- **涨不一定好——颜色语义必须绑定业务方向，不绑定数学符号**。退款率、错误率、延迟、成本上升是坏消息；处理量、转化率上升是好消息。语义色（成功、警告、危险）只允许用于**已声明方向**的指标。
- **翻转指标**（越低越好）必须在卡片或数据字典里显式声明方向，否则不得给涨跌上色，只给中性文字「上升 12%」。
- **红-绿有文化与语义含义**：NN/g 提醒 red 常被读作 bad / stop、green 读作 good / go。跨团队、跨文化分发时语义色要与企业品牌规范对齐，且任何时候都不能只有颜色——箭头符号与文字必须同时存在（WCAG 1.4.1：颜色不得是唯一手段）。
- **卡内迷你趋势图**按 §9 的 sparkline 边界执行。

## 八、无障碍

- **不得只靠颜色区分系列**（WCAG 1.4.1，Level A）。第二编码可选项：线型（首条实线，其余虚线/点线）、点形状、纹理（Carbon 允许）、直接标注。
- **明度差 ≥3:1 可以算作「颜色之外」的差别**（WCAG 1.4.1 的判定说明）：浅绿与深红同时差在色相和亮度上，达到 3:1 即通过。但若理解图表必须**准确辨认某一特定色相**（例如「绿色轮廓 = 有效，红色轮廓 = 无效」），则无论对比度多高都必须补一个非颜色的指示——WCAG 对此有明文要求。
- **图形对象对比 ≥3:1**（WCAG 1.4.11，Level AA），相邻色包括图元背后的绘图区底色，计算值不四舍五入。焦点环同属此处要求（≥3:1，且焦点环必须瞬时出现、不可淡入，见 `accessibility-baseline.md`）。
- **文字替代：图表不是「一张图」，而是非文本内容，必须给等价替代**（WCAG 1.1.1，Level A）：
  - **短替代**（图形说明或 `aria-label`）说明这是什么图、看什么；WCAG 给出的示例写法是「图一：6、7、8 月销量」。
  - **长替代**（`aria-describedby` 指向的说明段落，或图下正文）给出图表类型、数据的主要走势与含义，使读屏用户获得与看图者相当的信息。
  - **能表格化就给数据表**。WCAG 1.1.1 的示例明确写了「在可行且实际时，用表格给出实际数据」，这是长替代的最强形式，也是 `data-tables.md` 的适用场景。
  - **纯装饰的图元不加替代文本**，它们应被辅助技术忽略（WCAG 1.1.1 的「装饰、格式、不可见」条款），乱加 alt 反而干扰读屏。
- **可交互数据点的键盘可达**：每个可聚焦数据点必须有可访问名称（含系列名与数值，如「6 月，销量 1,240」）、可见焦点、≥3:1 的焦点指示；若实现键盘在数据点间移动，用 roving tabindex，Tab 只落在图表整体一次，进入后用方向键移动。
- **tooltip 不得只在悬停出现**：键盘 focus 与触屏点击必须同样能打开，且内容里包含两条轴的值（Carbon：tooltip 应重复该数据点在两轴上的取值及其他相关细节）。
- **极小扇区是不可访问的**：Carbon 明确——扇区小于 3° 时必须用引导线把标签与扇区关联；小于 **1°** 的扇区**根本不会被渲染**，该数据既不可键盘访问，也不出现在 tooltip 里，唯一读取途径是数据表。因此含 <1° 数据的饼图一律改数据表或条形图。
- **放大到 200% 时轴标签与图例不得被裁切或重叠**（工程判据，非某一来源条款；通过截图实测判定）。

## 九、密度与留白

- **纵横比建议**（经验区间）：时间序列折线 16:9 到 2:1（宽扁才读得出斜率）；柱状图与条形图 4:3 到 16:9；散点接近正方形（1:1 到 4:3，避免视觉斜率被拉伸误导）；饼图用外接正方形，不做椭圆。同一容器宽度下图高不一致，会被读成「两张图的重要性不同」——同层图表统一高度。
- **何时去掉网格与边框**：已加数据标签 → 删 Y 轴与网格线（NN/g，见 §3）；单系列且值已直接标注 → 删网格；**图元容器边框默认不要**——给整个图表加一圈描边是初级做法，分组应当靠留白与标题层级完成；轴线只保留承载刻度的左轴与底轴，上边与右边的框线删掉。
- **数据墨水比**：凡是删掉后不改变信息的元素都该删——这就是 chartjunk 的定义（NN/g 转述 Tufte 的 data-ink ratio 与 chartjunk 概念）。3D 效果、阴影、渐变填充、装饰纹理、背景图案都在此列，且 3D 与阴影还会造成对数值的视觉扭曲。
- **图内留白**：数据点距绘图区边界 ≥8px（经验区间）；柱顶标签与柱顶之间留空隙，不要让标签压住柱体。
- **迷你图（sparkline）的边界**：
  - **无坐标轴、无刻度、无标签、无图例、无网格**。它的职责是表达形状与方向，不是取值；一旦加上轴或刻度，就应该换成折线图（Carbon 把 sparkline 列为图表类型之一，其定位即「趋势形状」）。
  - 需要精确值、或需要比较两张 sparkline 的绝对高低时，sparkline 都是错的工具——换指标卡配基准，或换折线图。
  - **必须有可访问名称 + 一句趋势描述**（如「近 30 天订单量，整体上行，周末下探」），否则对读屏用户等于空白（WCAG 1.1.1 的非文本内容要求）。
  - 线宽 1.5–2px；放在指标卡内时高度 24–48px（经验区间）；数据点超过约 60 个后必须降采样或改画区间带（经验区间），否则逐点折线在窄高度下退化成噪声。
- **不要为了填满容器而拉伸图表**：容器留白是正常状态，图表被拉宽到没有留白时，视线在数据与轴标签之间的往返距离显著变长（与 `dashboard-console.md` §4 的宽度取舍同源）。

## 十、常见失败模式清单

前半是判定，命中即失败。

- 出现任何 3D 透视、阴影或渐变填充 → 失败。
- 柱状图或面积图 Y 轴不从 0 起 → 失败。
- 折线图或散点图截断 Y 轴但没有可见轴断裂标记 → 失败。
- 两条同类量各配一条 Y 轴塞进同一张图，或引入第三个量纲 → 失败。
- 用面积、角度、体积承载需要精确比较的量（饼图比相邻扇区、雷达图比数值）→ 失败。
- 用颜色表达数量大小；或分类色序不按固定顺序取用、循环取色；或用 HSL 色相环均分生成分类色（彩虹色序）→ 失败。
- 相邻系列或堆叠段的亮度差 < 3:1，灰度下无法区分 → 失败。
- 系列只靠颜色区分，没有线型、点形状、纹理或直接标注中的任何一种作为第二编码 → 失败。
- 图形对象与相邻色对比 < 3:1，或数据线细于 1px 导致实际对比低于计算值 → 失败。
- 图例按字母序排列、与堆叠顺序不一致；或默认显示超过两行无「查看更多」；或高度超过图高 30% 仍不滚动 → 失败。
- 图例、标题或轴标签使用缩写；隐藏图例且没有「查看图例」入口 → 失败。
- 标题只描述数据、不写出结论 → 失败。
- 参考线没有名称标签；注释超过 2 条、遮挡数据点，或与参考线混成第三套标记 → 失败。
- 数据缺口被插值连成曲线，或被静默补零 → 失败。
- 同一图内小数位不一致；单位写进刻度标签；同一页切换计量单位 → 失败。
- 指标卡没有基准对比，或趋势只有箭头而没有幅度与基准名 → 失败。
- 用红/绿表达涨跌却不声明业务方向；翻转指标（越低越好）直接套用「涨 = 绿」→ 失败。
- 趋势只有颜色，没有方向符号与文字 → 失败（WCAG 1.4.1）。
- 图表没有文字替代；或有替代但只描述了图表类型、没给出走势与含义 → 失败。
- 纯装饰图元带上了非空 alt → 失败。
- tooltip 只能通过鼠标悬停触发，键盘与触屏打不开 → 失败。
- 饼图中存在 <1° 的扇区，或 <3° 的扇区没有引导线 → 失败。
- 单个数据点被画成图表；或用指针仪表、半环仪表做精确比较 → 失败。
- sparkline 带上坐标轴或刻度，或没有可访问名称与趋势描述 → 失败。

## 十一、交付前自检清单（可打钩）

- [ ] 每张图的意图能用一个词说清（比较 / 构成 / 分布 / 相关性 / 随时间变化 / 排名），且图形与该意图匹配。
- [ ] 比较与排名类图表已按值排序，排序方向在图上可辨。
- [ ] 柱、面积、饼、堆叠条的数值轴从 0 起。
- [ ] 折线或散点的截断已带显式轴断裂标记，范围值、断点区间与线宽/点样式按 §2 处理。
- [ ] 没有 3D、阴影、渐变填充、装饰纹理。
- [ ] 双 Y 轴若存在，是「量 + 率」组合，且两轴均有单位、与系列视觉绑定。
- [ ] 主刻度 4–6 条，步长是 1/2/2.5/5/10 的 10 的幂；时间轴步长固定。
- [ ] 网格线比轴线浅一档；有数据标签的图已删掉冗余的 Y 轴与网格线；图上没有多余的容器边框与右侧/上方框线。
- [ ] 竖柱图标签无需旋转超过 45°；长标签已改用横向条形图；标签没有不可解缩写。
- [ ] 单位写在轴标题或卡片标签，未写进刻度标签；同页单位一致。
- [ ] 色序按用途选对：类别用分类色序、连续量用连续色序、有中点用发散色序；分类色序按固定顺序取用且类别数 ≤8；未使用彩虹色序。
- [ ] 相邻系列亮度差 ≥3:1；图表转灰度后仍能区分全部系列。
- [ ] 深色主题下连续色序的明度方向已翻转（最浅色为最大值）。
- [ ] 图形对象与相邻色 ≥3:1，文字与背景 ≥4.5:1；对比度计算值未取整。
- [ ] 一张图最多一个强调色，其余元素为灰阶。
- [ ] 单系列没有图例；多系列的图例与数据顺序一致，位置在底部或顶部。
- [ ] 图例不超过两行、高度不超过图高的 30%；未隐藏，或隐藏时带「查看图例」入口。
- [ ] 标题写的是结论，不是数据名；结论短语与对应数据元素同色。
- [ ] 参考线有名称标签；注释 ≤2 条且不遮挡数据。
- [ ] 缺失数据为断线并标注了缺口起止；补零仅用于实测为 0 的点且已注明。
- [ ] 同图同指标小数位一致；零线比网格线重一档。
- [ ] 每张指标卡都有基准（上期 / 目标 / 中位数）；趋势三件套（方向 + 幅度 + 基准名）齐全。
- [ ] 大数字 ≥32px 且 `tabular-nums`，无负字距。
- [ ] 涨跌配色绑定业务方向而非数学符号；翻转指标已声明方向。
- [ ] 系列不只靠颜色区分，有第二编码。
- [ ] 每张图有短替代与长替代；可表格化的图已附数据表；纯装饰元素对辅助技术隐藏。
- [ ] tooltip 可键盘触发、可触屏触发，内容含两轴取值；可交互数据点有可访问名称与可见焦点。
- [ ] 无 <1° 扇区；<3° 扇区已用引导线关联标签。
- [ ] sparkline 无轴无刻度，有可访问名称与趋势描述，高度 24–48px，超 60 点时已降采样。
- [ ] 200% 放大下轴标签与图例不裁切、不重叠。
- [ ] 桌面与移动至少两档截图亲眼看过后才交付。

6. **Financial Times — Visual Vocabulary（Chart Doctor 仓库 README）** — https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md — 用途：按数据关系组织图形选型（Deviation、Correlation、Ranking、Distribution、Change over Time、Part-to-Whole、Magnitude、Spatial、Flow）；Magnitude 类的**柱与条必须从 0 起**、棒棒糖图「不必但从 0 起更好」；Part-to-Whole 中饼图难以准确比较扇区大小、堆叠柱超过少数组件就难读；Change over Time 中折线是不规则时间序列的标准做法、列图最好只放一条系列；相关性的默认解读是因果，除非明确说明；双轴相关讨论与 line + column（量 + 率）的合法用法。**该文件全文本人经 jsDelivr 镜像 https://cdn.jsdelivr.net/gh/Financial-Times/chart-doctor@main/visual-vocabulary/README.md 抓取读取**（GitHub 页面本身仅返回被截断的导航）。许可：页面声明 Copyright © The Financial Times Limited, all rights reserved（版权保留，再发布需联系其授权部门）；本文仅引述其分类框架与结论，未搬运海报图或示例图。
7. **Nielsen Norman Group — Dashboards: Making Charts and Graphs Easier to Understand** — https://www.nngroup.com/articles/dashboards-preattentive/ — 用途：前注意加工的编码强度次序——长度与二维位置既快又准，适合承载定量信息；面积与角度只能看出「有差别」而无法判断差别多大；**颜色不得用于表达定量值或量级**；柱状图与散点/折线的编码依据；色觉缺陷比例量级（男性约 8%、女性约 0.5%，随族群变化）。许可：页面声明 Copyright © 1998-2026 Nielsen Norman Group, All Rights Reserved；本文仅引述结论与阈值。
8. **NN/g — Choosing Chart Types: Consider Context** — https://www.nngroup.com/articles/choosing-chart-types/ — 用途：3C 框架（Context / Clutter-free / Contrast）中的 Context；「人必须拿一个数去比另一个数才能解释它」；大多数场景只用柱、折线、散点三种；分组柱的分组维度应按「你想让人做的那个比较」来定，把要比较的两项放近；长标签用横向条形图，不要旋转或缩写；能直接展示差异（如百分比变化）就不必给分组柱，百分比变化可写进标题。许可同上。
9. **NN/g — Clutter-Free: One of the 3 Cs for Better Charts** — https://www.nngroup.com/articles/clutter-charts/ — 用途：data-ink ratio 与 chartjunk 的定义（Tufte）；3D 效果、阴影、渐变、纹理不增加信息且会扭曲感知；加数据标签后 Y 轴与网格线成为冗余可删，反之若只需量级感则保留网格线而不加标签；整档抬高轴单位以减少网格线与标签；轴标签在标题已明确指标与单位时可不加。许可同上。
10. **NN/g — Contrast: One of the 3 Cs for Better Charts** — https://www.nngroup.com/articles/contrast-charts/ — 用途：「先全灰再上色」的强调色纪律（Schwabish）；标题写结论（active title）的对照示例；标题与图内元素同色可建立关联；注释/callout 让上下文随图一起被转发；避免亮度相近的纯色（色盲用户难区分），用不同深浅加不同色相；红与绿有跨文化语义，发布前对齐品牌规范。许可同上。
11. **W3C WCAG 2.1 理解文档 — 1.4.1 颜色的使用（Level A）** — https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html — 用途：颜色不得作为传达信息、指示动作、提示响应或区分视觉元素的唯一手段；**颜色若同时存在显著亮度差并达到 3:1 对比，可算作额外的视觉区分**；但若内容依赖用户准确辨认某一特定色相，则无论对比度多高都必须追加非颜色指示。许可：W3C 文档许可（页脚声明适用 W3C 软件许可与商标规则）。
12. **W3C WCAG 2.1 理解文档 — 1.4.11 非文本对比度（Level AA）** — https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html — 用途：界面组件与**理解内容所必需的图形对象**与相邻色对比 ≥3:1；计算值不四舍五入（2.999:1 不合格）；抗锯齿会让细线与小图形实际更淡，故应避免极细线条或选高于阈值的配色；焦点指示的对比要求。许可同上。
13. **W3C WCAG 2.1 理解文档 — 1.1.1 非文本内容（Level A）** — https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html — 用途：图表属非文本内容，必须有等价文字替代；图表类内容适用 Situation B——短替代（简要说明）**加**长替代（描述类型、高层摘要、趋势与含义）二者都要；示例明确「在可行且实际时用表格给出实际数据」；纯装饰内容应实现对辅助技术的忽略。许可同上。
