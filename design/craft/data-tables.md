# Data table craft rules

数据表格的跨品牌工艺规则。`DESIGN.md` 决定表格长什么样（配色、圆角、字体），本文决定**它必须先满足哪些结构、语义与状态条件才算合格**。多数 AI 生成的「表格」只交付了一个静态的、对齐混乱的、加载时留空的 `<table>`。

> 依据一手来源整理：GOV.UK Design System（Table）、USWDS（Table 与 Table accessibility tests）、IBM Carbon Design System（Data table 的 Guidelines / Accessibility）、W3C ARIA APG（Table Pattern、Grid and Table Properties）、MDN（HTML table accessibility、`font-variant-numeric`、`text-overflow`）。逐条对应见文末「来源」。

## 一、什么时候用表格，什么时候不该用

判据只有一条：**这批数据是否同时在「行」和「列」两个维度上可比较。** 只有一列可比的，是列表，不是表格。

- **同一实体的多个属性需横向对比** → 表格。前提是列数 ≥ 3，且存在「同一量纲、逐行可比」的列；代价是移动端必须降级（见 §2.5）。
- **只需按单一维度排序的一串条目** → 列表（列数 = 1，或只有一条属性是决策依据）。放弃横向对比能力。
- **每条自带图、标题、描述、多个 CTA** → 卡片栅格（条目间存在层级差异，视觉比数值更重要）。信息密度最低。
- **查看 / 编辑单个记录的全部字段** → 定义列表（行数 = 1，字段是「名-值」对而非可比数据）。不能排序、不能筛选。
- **表体嵌大量输入控件（可编辑单元格）** → 网格 grid（需要方向键在单元格间移动、区域复制）。代价是失去原生表格语义，须手工补 ARIA。
- **用表格排页面版式** → **禁止**。GOV.UK 明确禁止，版式一律用栅格系统。

三条判定细则：

1. **列数 < 3 且行数 < 5** — 不要用表格，用定义列表或段落；表头与边框的开销在这种规模下大于收益。
2. **存在「总计 / 小计」行** — 只有 `<tfoot>` 能承载，卡片不行；这是选表格的正向信号。
3. **条目需跨页比较** — 只有表格提供稳定的列坐标；卡片化后用户在第二页无法对照第一页。

反面清单：用表格做版式（导航、页脚、左右分栏）会让读屏把整页念成一张巨型表格；把表格当电子表格用（公式、多单元格区域选择）被 Carbon 明确不建议——数据表格不应替代电子表格应用；用表格做「伪进度条 / 伪看板」不属于表格的语义职责。

## 二、列的设计

### 2.1 对齐与数字格式（无例外）

- **数字、金额、百分比、序号 / 排名** → **右对齐**。GOV.UK：比较成列数字时右对齐，位数不同也能按位比较；序号与数字同列族，左对齐会随位数变化抖动。
- **短文本（名称、ID、标签）、长文本（描述、备注）、日期、状态 / 徽标** → 左对齐。日期是时间轴上的标签而非数量，**不要**右对齐；徽标宽度可变，右对齐会让右边缘参差。长文本对齐后需截断，见 §6.4。
- **操作列** → 右对齐或居中，通常固定最右；**选择列** → 左对齐占首列。两者都固定宽度。
- 右对齐必须同时开等宽数字，否则等于没对齐；若正文用了 oldstyle 数字（3/4/7/9 带降部）或比例数字，须在该列显式覆盖，否则数字会上下跳动：

```css
.cell-num {
  text-align: right;
  font-variant-numeric: tabular-nums; /* OpenType tnum；Baseline 广泛可用 */
}
```

- 同列小数位数**必须一致**（混排 `3.5` 与 `3.50` 会破坏右对齐的可比性），千分位分隔符必须使用（`1,234,567`）；单位属于列头而非单元格——列头写「金额（元）」，单元格只放数值（逐格重复单位会让数字列退化为文本列）。
- 空值不写 `0`、不写 `-`，用「—」表示缺失并保持右对齐；`0` 与「无数据」语义不同，混用会让用户误判汇总。负数用真负号 `−`（U+2212），或至少在 `tabular-nums` 下保持等宽；不用括号伪装负数，除非财务语境已有约定。

### 2.2 状态列

状态必须是「形状 + 文字」，不得只靠颜色（WCAG 1.4.1；USWDS 表格测试项明确检查「颜色不是传达含义的唯一方式」）：始终有可读状态词（「已完成」「失败」），配色块或图标作为第二编码，文字与底色对比度 ≥ 4.5:1（WCAG 1.4.3，USWDS 测试项）。状态取值收敛到 4–6 个；超过 6 个说明它其实是分类字段，应改为筛选。

### 2.3 列宽策略

- **内容自适应**（`table-layout: auto`，默认）— 适用于列少、内容短、行数少；代价是列宽随数据抖动，筛选后同名列突然变宽。
- **固定布局**（`table-layout: fixed` + 列头百分比宽度）— 适用于列多、需稳定坐标、主列内容长；代价是强制截断，必须配 §6.4 的展开方式。
- **混合**（主列 `width: 40%`，数字列给最小宽度）— 适用于绝大多数业务表格；代价是需随列配置维护一份列宽表。
- 表格宽度**不要默认 `width: 100%`**。GOV.UK 社区讨论的结论是表格只应宽到内容所需——过宽的表格让视线在行内长距离跳跃。内容不足时用 `width: auto`。
- 数字列给最小宽度而非定宽，避免 `±1,234,567.89` 被折成两行；列宽必须在**筛选、排序、分页之后保持不变**，随数据重算是表格最常见的「AI 味」缺陷。

### 2.4 列优先级与响应式降级

先给列打优先级，**P0 是行身份（名称 / ID）+ 当前任务主指标，任何宽度都必须可见**；P1 是决策必需的次要数值，≥ 768 px 显示；P2 是补充与诊断信息，≥ 1024 px 显示；P3 是审计 / 元数据（创建时间、创建人 ID），不进表格、只进详情。

降级方案三选一（代价必须写进设计说明）：

- **隐藏次要列** — 640–768 px 起逐级隐藏；代价是窄屏下用户可能无法完成对比任务。
- **容器横向滚动** — 全宽度；容器需 `tabindex="0"` 才能聚焦滚动。USWDS 实测：JAWS / NVDA 下方向键**不会**滚动容器，离屏数据会被念出但键盘无法跟随焦点（WCAG 2.1.1 记为「通过但有例外」）。
- **卡片化（堆叠）** — < 640 px；代价是一屏可见行数骤降、跨行比较消失，须把列头复制进每张卡片。
- 补充方案：**冻结首列 + 横向滚动**（中宽），实现最复杂，粘性定位与行高 / 折行易冲突。

USWDS 的堆叠实现可直接借鉴：窄屏把每个单元格变成一行「列头：值」，列头文本取自 `data-label` 属性；若同时保留表头，必须保证两者语义不冲突（不要让读屏把列头读两遍）。

## 三、行与密度

### 3.1 行高

以 Carbon 的实测档位为准，**表头行高必须与数据行一致**（Carbon 明确要求 thead 与行尺寸匹配，混用是被点名的反例）：超小 24 px（极限密集，人在其中「查数」而非「读表」）｜小 32 px（紧凑界面）｜中 40 px（默认档，无特殊密度要求时用它）｜大 48 px（宽松布局、需要强调与易点击）｜超大 64 px（仅当单元格内预期有 2 行内容）。

自检阈值（经验区间）：单行内容行高 < 28 px 时触控目标已不足，移动端禁用；< 32 px 且行内还有图标按钮时误触率明显上升。**不要在 40 px 与 48 px 之间临时取 44 px 这类非标值**——密度档位必须离散，否则「舒适档」会退化成随意值。

### 3.2 斑马纹纪律

斑马纹（交替底色）是补偿手段，不是装饰。

- **可用**：行高 ≤ 32 px 且无横向分隔线——密集时条纹比线更少视觉噪声。
- **禁用**：行高 ≥ 40 px 且有分隔线（两者冗余，视觉变脏）；行内已有条件着色（状态底色、高亮）——条纹与语义色打架，语义色优先；需要明显的悬停 / 选中反馈——条纹削弱 hover 的对比落差；打印 / 导出——灰度打印下条纹失效，反而降低文字对比。
- 条纹对比度必须极低：与白底亮度差建议 < 6%（经验区间），且不得低到行边界消失；条纹底色上的文字仍须满足 4.5:1。

### 3.3 分隔线、悬停、选中

分隔线以水平线优先，垂直线是加分项而非必需；**线与条纹择一为主**，同时满配是初级做法；表头下边线可比行间线重一档，它是语义边界而非普通分隔。悬停态整行着色并横向贯通到表格两端（含冻结列），不要只给单元格上色；选中态必须**强于**悬停态且可叠加区分（悬停浅灰，选中为低饱和强调底 + 左侧 2–3 px 强调条）。行内易变区域（按钮、链接）随行悬停出现时，必须**同时**在键盘 focus 时出现，否则键盘用户永远看不到操作入口（WCAG 2.4.7）。

## 四、表头

### 4.1 表头不可省略的语义

即使视觉上「表头很明显」，语义也不能省（GOV.UK：用 `scope` 帮助辅助技术区分行头与列头；MDN：`<caption>` 用来说明表格内容）：

```html
<table>
  <caption>2026 年 3 月各车型月票费率</caption>
  <thead><tr><th scope="col">适用月份</th><th scope="col">自行车费率</th></tr></thead>
  <tbody><tr><th scope="row">1 月</th><td>£85</td></tr></tbody>
</table>
```

- `<caption>` 必须存在：它是读屏用户判断「这张表值不值得读」的唯一入口。`<table summary>` 已废弃，MDN 明确建议改用 `<caption>`。
- 首列是行身份时用 `<th scope="row">` 而非 `<td>`（GOV.UK 的 `firstCellIsHeader` 即此事）；表头不得用 `<div>` + 加粗文本伪造。
- 跨行 / 跨列用原生 `rowspan` / `colspan`，不要手工加 `aria-rowspan` / `aria-colspan`（那是给非原生表格结构的）。
- 表头文字不要缩写到不可解：空间不足时缩短而非删词，「完成率」好过「完成」。

### 4.2 吸顶与排序

- 数据行超过约 **12–15 行**（经验区间）后吸顶才值得做；行数少时吸顶只是噪声。用 `position: sticky; top: 0` 且必须设 `z-index`，否则会被单元格内容盖住；需有底边线或极轻投影以区分悬浮层，用重投影是过度装饰。
- 容器 `overflow: hidden` 会裁掉外扩的 `outline`，吸顶后焦点环不得被裁；横向滚动时吸顶表头必须与表格同速横移（用两个独立滚动容器是最常见做法，也是最常见的错位来源）。
- 可排序列头必须是可聚焦控件（`<button>`），Tab 可到达，`Space` / `Enter` 触发（Carbon：列头可 Tab 到达并以 Space 或 Enter 排序）；**不可排序的列头不要放灰色箭头**，那会让人反复点击。
- 排序状态用 `aria-sort` 表达，取值见 APG：`ascending`、`descending`、`other`（以非升 / 降算法排序，如相关性、自定义优先级）、`none`（未排序）。**`aria-sort` 加在该列的表头单元格上，不是按钮上。**
- 图标：悬停或聚焦时露出「可排序」双箭头，已排序列常驻显示当前方向（Carbon：排序指示在悬停与聚焦时出现，已排序列保留指示）。不得用纯色三角表示状态而没有文字或可访问名称；视觉图标必须有可访问名称（如 `aria-label="按金额排序"`），否则读屏只能听到箭头符号（WCAG 4.1.2）。
- 三态循环：未排序 → 升序 → 降序 → 未排序（回到默认顺序），不要让用户困在排序里出不来。排序完成后必须播报结果（「按金额升序，共 128 条」）。
- **多列排序**：APG 有一条硬约束——**ARIA 无法表达多键排序的层级**，对多个列同时设非 `none` 的 `aria-sort` 价值有限。首选「单列排序 + 固定次级排序键」（如始终以创建时间兜底），对读屏完全可表达；确需多键时把状态写成可见的「排序胶囊」（`金额 ↑ → 创建时间 ↓`），`aria-sort` 只标主键，其余靠胶囊文字与播报表达，并保证多键配置能一键清空。

## 五、交互

### 5.1 筛选、搜索与分页

搜索框与筛选器放表格工具栏（Carbon 的工具栏定位：主按钮、搜索、筛选、表格显示设置），工具栏高度应与行高档位配对。筛选条件必须**可见且可移除**：每个生效筛选项以可点掉的标签呈现，并有「全部清除」；筛选后必须更新结果计数（「128 条中的 23 条」）并在动作后播报。服务端筛选必须防抖 **250–500 ms**（经验区间），本地筛选不需防抖。筛选无结果与真·无数据是两种文案，见 §6.2。

| 维度 | 分页 | 无限滚动 |
|---|---|---|
| 定位到第 N 条 | 可直达、可分享 URL | 只能滚 |
| 到达页脚 | 可以 | 永远够不到 |
| 数据总量感知 | 有总页数 | 无 |
| 键盘可操作性 | 好 | 滚动触发不可键盘控制 |
| 移动端手势 | 一般 | 好 |

**表格默认分页。** 只有「以浏览为目的、不定位、不跨页比较」时才允许无限滚动；表格的核心任务是定位与比较，与无限滚动直接冲突。分页要件：显示当前范围与总数（「21–40 / 共 128 条」，不要只显示页码）；每页条数提供 **10 / 25 / 50 / 100** 四档（经验区间），默认 25，切换后回到第 1 页；分页控件必须是真链接或真按钮，键盘可操作且有可见焦点（GOV.UK 有独立 Pagination 组件，不要自造）；每页条数、排序、筛选、页码必须同步进 URL；服务端分页时行索引不能直接当「序号」列——第 2 页的序号应从 26 起算。

### 5.2 批量选择

条列独立成列并固定最左，宽度固定；单选用 radio，多选用 checkbox（Carbon 的 selection 变体即这两种）。表头全选是三态：全不选 / 全选 / **部分选中（indeterminate）**——缺第三态，用户在跨页场景会误判。**跨页选择的歧义必须显式解决**，二选一：**本页语义**（翻页即清空，表头提示「已选 3 项（本页）」）或**跨页语义**（翻页保留，工具栏常驻「已选 47 项（全部 128 项中的）」并提供「清空选择」）；反例是选择静默跨页保留、文案却写「本页」——用户以为只删 3 条，实际删了 47 条。批量操作条位于表格上方（或悬浮），必须包含已选计数、可执行动作、清空入口；破坏性动作必须二次确认，且确认文案带**具体条数**，不带条数的「确定删除？」等于没有确认；选择状态变化要播报（「已选 25 项」）。行级 checkbox 必须有可访问名称并含行身份（如 `aria-label="选择 订单 A-1024"`），不能是一列无名 checkbox。

### 5.3 行内操作与溢出菜单

每行最多暴露 **1–2 个**高频动作（建议：主操作 + 溢出菜单），其余收进溢出菜单；触发按钮必须有可访问名称且含行身份，否则读屏听到 50 个「更多」。溢出菜单不得被表格容器 `overflow` 裁切——`overflow: auto` 的滚动容器是行内下拉菜单最常见的裁剪来源，无法避免时用 portal 渲染到 `body`。行内操作「悬停才出现」时，隐藏的只能是视觉而非可访问性：用 `opacity: 0` 而非 `display: none`，并在 `:focus-within` 时恢复可见；触屏不存在悬停，粗指针设备上行内操作必须常驻可见（`@media (hover: none)`）。

## 六、数据状态

表格需要四种状态：**加载、空、错误、有数据**。边界情况（超长文本、窄屏、超大数据集）通过 §2.4 与 §6.4 解决，不额外增加独立视觉状态。加载、空、错误三态的具体内容如下。

- **加载** — **绝不能只留一张空表**，否则用户无法判断是在加载还是真的没数据。首次加载、无缓存 → 骨架屏，按预期行数渲染 **8–12 行灰色块**（经验区间），列宽使用已知列配置，不要用随机宽度；已有数据、重新筛选或翻页 → 保留旧数据 + 降低透明度 + 顶部细进度条，**不要**清空成骨架，否则内容闪烁；局部刷新（单行）→ 该行内联 loading，其余行不动；排序中 → 表头排序按钮进入 loading 态，表格内容保持可见。骨架行数应与每页条数一致（每页 25 就画 25 行骨架），行数突变比没有骨架更难受；骨架必须 `aria-hidden="true"`，并用礼貌型实时区域播报「加载中」，不要让读屏逐格朗读占位块。请求超时必须存在：15 s 仍未返回时给出「比预期更慢」提示（与 `state-coverage.md` 阈值一致），60 s 转错误态。
- **空（两种，绝不混用）** — **无数据（first-use）**：系统里本来就没有记录，必须包含一句说明「还没有订单」+ 数据用途的一句话，出口动作是主 CTA「创建第一笔订单」。**筛选无结果**：有数据但当前条件命中 0 条，必须**回显当前筛选条件** + 建议放宽的方向，出口动作是「清除筛选」「重置关键词」。**筛选 + 无数据** → 按「无数据」处理；**权限为空**（有数据但当前账号无权限）→ 说明是权限原因，出口是「申请权限」或联系入口。无数据与筛选无结果都应保留列头（让用户知道这表将来有什么列），只把表体换成空态块。禁止文案：只写「暂无数据」四个字，缺说明、缺出口；筛选无结果的说明里必须包含用户输入的原词，否则用户不知道自己筛了什么。
- **错误（三层，不要一律整页报错）** — **页面级**：首次加载失败 → 表格区域整体替换为错误块，含原因、重试按钮、可复制的错误 ID；**区域级**：刷新失败但已有数据 → 保留旧数据，顶部横幅提示「数据可能不是最新」，附重试；**行级**：单行操作失败 → 该行内联错误，其余行可用，不要把整张表回滚。错误文案必须回答三问（见 `state-coverage.md`）：发生了什么、为什么、现在能做什么。「加载失败」不算文案。

### 6.1 超长文本截断

截断是必须的，但截断**不能是终点**。

- **单行省略号** — `overflow: hidden; white-space: nowrap; text-overflow: ellipsis`，用于短标识类（邮箱、ID、路径）；**多行截断** — `-webkit-line-clamp` + `display: -webkit-box`，用于描述、备注；**折行不截断** — `overflow-wrap: anywhere`，用于内容本身短、列宽足够的场景。
- `text-overflow` **不会**自己触发溢出，必须同时设 `overflow: hidden` 与 `white-space: nowrap`（MDN）。三者缺一，省略号不出现。
- 截断必须提供展开方式，二选一：整格内容用 `title` / tooltip 完整显示，或点击展开该行（Carbon 的 expandable 变体就是为「在有限空间里放大信息量」设计的）。只有省略号没有展开是数据丢失。tooltip 方案对键盘与触屏必须同样可达：`title` 在触屏上不可靠，需配可见的 focus 触发与点击触发。
- 关键身份列（名称、ID）**优先折行，不要截断**，截断 ID 会让用户无法核对工单号；中长英文单词与 URL 必须 `overflow-wrap: anywhere`，否则会撑破列宽并把整张表挤进横向滚动。多行截断的行要 `align-items: start` 并统一 `line-clamp` 行数（建议 2 行），避免单元格高度参差。

## 七、无障碍

- **原生优先** — 用原生 `<table>`（含 `<caption>` / `<thead>` / `<th scope>`），不要用 div 拼 ARIA 表格（APG Table Pattern 明确「原生等价存在时使用原生元素」）。
- **表格名称与说明** — 必须有可访问名称：可见标题用 `aria-labelledby` 指向它，否则用 `aria-label`；有补充描述时用 `aria-describedby` 指向描述元素（APG；Carbon 亦要求提供 `aria-label` / `aria-labelledby` / `title`）。
- **排序播报** — 排序列的 `th` 上设 `aria-sort`；读屏须能读出「是否排序、如何排序」（APG / USWDS 测试项）。
- **键盘路径** — 表内链接、输入、排序按钮、展开箭头全部进入 Tab 序列并保持常规键盘操作（Carbon；USWDS「焦点不被囚禁」「焦点指示可见」）。
- **横向滚动容器** — 加 `tabindex="0"` 才可聚焦滚动；须知方向键在部分读屏下不滚动容器（USWDS 已记录的例外）。
- **颜色与放大** — 颜色不得是传达含义的唯一方式，文字对比 ≥ 4.5:1；200% 放大下内容不重叠、不裁切、功能可用（USWDS 测试项，WCAG 1.4.1 / 1.4.3 / 1.4.10）。
- **大数据集索引** — DOM 中行 / 列不全时补 `aria-rowcount` / `aria-rowindex`（1 起算），否则读屏行读取会跳行甚至失效；列被隐藏但仍在数据集中时用 `aria-colcount` + `aria-colindex`——连续列可只标在行上，不连续必须逐格标（APG Grid and Table Properties）。
- **合并表头** — 原生表格用 `rowspan` / `colspan`，非原生结构才用 `aria-rowspan` / `aria-colspan`（APG）。
- **可点击行的实现与陷阱** — **推荐**：行身份单元格里的链接用 `::after { position: absolute; inset: 0 }` 铺满整行来扩大点击区，语义、右键、新标签打开、键盘焦点全部免费。**反例**：给 `<tr>` 加 `onclick` 而不给键盘路径——鼠标能点、Tab 到不了、回车无反应；`<tr tabindex="0" role="button">` 更糟，`role="button"` 会**摧毁**该行的 `row` 语义，读屏不再把它当表格行，列头关联随之丢失；行内同时有 checkbox 与整行点击、点 checkbox 也触发跳转——必须 `stopPropagation` 并给 checkbox 独立可访问名称；行内含需要选中的文本（工单号、邮箱）却整行可点，选择行为被破坏，这类表格应改为「首列链接」方案。行可点击时用 `cursor: pointer`，悬停高亮覆盖整行。
- **必须播报的四条** — 进表时播报 caption；排序后播报「按 X 降序，共 N 条」；筛选后播报「筛选后 N 条」；选择变化播报「已选 N 项」。加载用礼貌型 `role="status"`，错误用 `role="alert"`；实时区域容器必须在注入内容**之前**就存在于 DOM 中。

## 八、常见失败模式与交付前自检

每条前半是判定（命中即失败），后半是交付前必须打钩的自检项。逐条核对，一条不过就说明表格工艺未达标。

- 用 `<table>` 做版式 → 失败。自检：列数 ≥ 3，不满足时已改用列表 / 卡片 / 定义列表。
- 数字列左对齐，或右对齐但没开 `tabular-nums`（等于没对齐）；日期列与状态列右对齐 → 失败。自检：数字列右对齐且已设 `font-variant-numeric: tabular-nums`，日期与状态列左对齐，单位在列头不在单元格。
- 同列小数位数不一致，或空值写成 `0`；状态只用颜色表达、没有文字 → 失败。自检：同列小数位数一致，空值显示为「—」而非 `0`，状态列有文字且文字对比 ≥ 4.5:1。
- 列宽在筛选或排序后重算抖动；未标注列优先级，窄屏下 P0 列反而被隐藏 → 失败。自检：已声明列宽策略（auto / fixed / 混合）且筛选排序后列宽不变，已给每列标 P0/P1/P2/P3 并写明降级方案与代价。
- 表头行高与数据行高不一致；同时使用斑马纹与行分隔线；选中态与悬停态无法区分，或选中弱于悬停 → 失败。自检：行高取自离散档位（24 / 32 / 40 / 48 / 64）且表头与数据行一致，斑马纹与分隔线不同时使用、仅在行高 ≤ 32 px 时启用，选中态强于悬停态且可叠加区分。
- 表头缺 `<caption>`，或首列行身份用 `<td>` 而非 `<th scope="row">`；表头吸顶未设 `z-index`，或被容器裁掉焦点环 → 失败。自检：`<caption>` 存在，列头 `scope="col"`、行头 `scope="row"`，吸顶（行数 > 12–15）已设 `z-index` 且不裁焦点环。
- 可排序列头不可 Tab 聚焦，或排序只靠鼠标；排序列未设 `aria-sort`，或把 `aria-sort` 加在按钮上 → 失败。自检：可排序列头是 `<button>`，Tab 可达、Space / Enter 可用，`aria-sort` 加在 `th` 上且三态循环可回到未排序。
- 对多列同时设非 `none` 的 `aria-sort` 且无可见排序胶囊；排序 / 筛选 / 选择变化无任何播报 → 失败。自检：多列排序有可见排序胶囊或已退化为单列 + 固定次级键，排序、筛选、选择变化均有实时区域播报。
- 筛选条件生效后不可见、不可单独移除；表格默认无限滚动；分页不显示「当前范围 / 总数」 → 失败。自检：筛选条件可见、可单独移除、有「全部清除」且结果计数已更新，表格用分页并显示「X–Y / 共 N 条」。
- 每页条数 / 排序 / 筛选 / 页码不同步到 URL → 失败。自检：每页条数 10 / 25 / 50 / 100，默认 25，切换后回到第 1 页，并已同步到 URL。
- 跨页选择语义未声明，表头全选缺 indeterminate 态；行内 checkbox 是无名控件；破坏性批量操作确认框不含具体条数 → 失败。自检：批量选择语义已声明（本页 或 跨页），跨页时工具栏常驻已选计数与清空，表头全选有 indeterminate 态，行内 checkbox 可访问名称含行身份，破坏性二次确认含具体条数。
- 溢出菜单被 `overflow: hidden` 的表格容器裁切；每行直接动作超过 2 个；行悬停才出现的操作在键盘 focus 时不出现 → 失败。自检：每行最多 1–2 个直接动作且溢出菜单不被裁切，行内操作在 focus 与粗指针设备上均可见。
- 加载时只留空白表体（无骨架、无 spinner、无文案）；骨架行数与每页条数不一致，或骨架列宽随机 → 失败。自检：加载态有骨架（8–12 行或等于每页条数）、列宽用已知配置、`aria-hidden`，二次加载保留旧数据不清空成骨架。
- 「无数据」与「筛选无结果」共用同一句文案；空状态只有「暂无数据」缺说明缺出口 → 失败。自检：无数据与筛选无结果使用两套文案与两个出口。错误一律整页报错且文案不含原因与恢复动作 → 失败。自检：错误按页面级 / 区域级 / 行级分层，文案回答「发生了什么 / 为什么 / 能做什么」。
- 超长文本只有省略号、没有展开路径；关键 ID 列被截断 → 失败。自检：截断三件套齐全（`overflow` + `white-space` + `text-overflow`）且有展开路径，关键 ID 与名称列折行不截断。
- 用 `role="button"` 或裸 `onclick` 实现可点击行；横向滚动容器没有 `tabindex="0"` → 失败。自检：可点击行用链接铺满方案，横向滚动容器已加 `tabindex="0"`，并已知晓方向键滚动在部分读屏下不生效。
- 用 `aria-rowcount` 却只在部分行上设 `aria-rowindex`（APG 警告会导致读屏跳行或停止工作） → 失败。自检：DOM 行 / 列不全时已正确设 `aria-rowcount` / `aria-rowindex`（全部行，1 起算）。
- 键盘走查缺失（Tab 顺序混乱、焦点不可见、存在焦点陷阱）；200% 放大下内容重叠或裁切；从未用读屏实际听过表格 → 失败。自检：键盘走一遍确认 Tab 顺序合理、焦点可见、无焦点陷阱，200% 放大下内容不重叠不裁切，并用读屏实际听一遍进表、排序、筛选、选择四条播报。
