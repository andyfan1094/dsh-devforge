# 截图自检提示词

> **用途**：界面"写完了"和"能交付"之间差一次真实的看图。凭代码想象出来的版式，与浏览器渲染出来的版式经常不是一回事。
> **铁律**：桌面与移动**至少两档**截图看过再交付。没看过就交付，等于没验收。
> **配套**：逐条判定标准见 `craft/anti-slop-unified`；数值底线见 `craft/craft-floor`。

## 拍摄档位

| 档位 | 宽度 | 必看内容 |
| --- | --- | --- |
| 移动小 | 320px | 是否横向溢出、触控目标、字号是否过小 |
| 移动大 | 390px | 首屏信息是否成立、换行是否产生孤字 |
| 平板 | 768px | 栅格折行是否合理、有没有"半吊子"中间态 |
| 桌面 | 1440px | 主次层级、行宽是否过长、留白是否失衡 |

至少拍 320px 与 1440px 两档；有平板断点时必须补 768px。

## 提示词正文

```text
你要对刚完成的界面做交付前截图自检。逐条核对，每条给「通过 / 不通过 / 不适用」，
不通过的必须写出：在哪个档位、什么现象、怎么改。不许只写"整体不错"。

A. 首屏成立性
   1. 320px 下是否出现横向滚动条
   2. 首屏能否看出"这是什么产品、下一步做什么"
   3. 主操作是否只有一个最强入口

B. 层级与排版
   4. 是否存在唯一的主导元素；若都在抢，指出抢的两个
   5. display 级标题的字体是否落在被滥用的默认脸（Inter / Roboto 等）上
   6. 正文行宽是否落在 45 到 75 字符之间
   7. 正文字号与行高是否落在可读区间（正文 ≥ 15px，行高 ≥ 1.5）

C. 颜色与对比
   8. 强调色是否只有一个；有没有紫蓝渐变或渐变文字
   9. 正文与背景对比度是否 ≥ 4.5:1；大字号 ≥ 3:1
   10. 状态是否只靠颜色表达（色盲不可辨即不通过）

D. 交互与状态
   11. 键盘 Tab 一遍：焦点环是否处处可见且瞬时出现（不可淡入）
   12. 是否存在 transition: all 或对布局属性的过渡
   13. 加载 / 空 / 错误三态是否都真实渲染过；空态是否有出口
   14. 交互目标是否 ≥ 44×44px（移动端）

E. 内容诚实性
   15. 是否存在占位文案（lorem ipsum、功能一/功能二）、编造的指标或客户名
   16. 数字列是否右对齐并使用等宽数字
   17. 有无 emoji 被当作功能图标

输出格式：先给一张通过情况表，再给按严重度排序的问题清单（每条含档位、现象、改法），
最后给一句结论：可否交付。
```

## 结论口径

- 出现 P0 问题（横向溢出、焦点不可见、编造数据、渐变文字、emoji 图标）→ **不可交付**，改完重拍。
- 只有 P1/P2（间距不均、次级对比度偏弱）→ 可交付但须登记待办；不允许"下次一起改"超过一轮。
- 自检必须基于**真实截图**。没有截图就说"未自检"，不要用"看起来没问题"代替。
